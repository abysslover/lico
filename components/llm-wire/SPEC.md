# lico-llm-wire 0.1.0 — specification

This file is the contract; `tests/contract.rs` states each line as a test. The marks say where a line comes from: **KNOWN FROM DOCUMENTATION** (a fact about the two APIs from their public documentation, never checked against a server; the fake server of M16-P04 is its contract), **SEEN IN CODE**, **PROPOSED**. The version is `0.1.0` until the owner allows one check against a real loopback server.

## Specification (approved by the owner on 2026-11-17) `llm-wire` (component `components/llm-wire`, crate `lico-llm-wire`, library `lico_llm_wire`)

| Line | Content | Mark |
|---|---|---|
| Purpose | Pure translation between Lico's neutral conversation types and the bytes of two chat APIs: build the request body; read a reply (a whole body, or a stream, in any split into pieces) into neutral events; read a failure; read an Ollama model's facts. No IO, no clock, no randomness, no files, no network, no global state, no text cleaning. | PROPOSED |
| Dependencies | `serde_json =1.0.154` with `default-features = false`, `features = ["std"]` (the program's own pin) and `std`; no other crate, no module of the program. Direction: the host adapter depends on it, never the reverse. Layer 0. | SEEN IN CODE (`Cargo.toml` pin) / rest PROPOSED |
| Layout and rules | `components/llm-wire/` with `Cargo.toml` (`[package.metadata.lico]`: purpose, spec, `depends = []`, budget 256 MiB and 30 s), `SPEC.md`, `src/lib.rs`, `tests/contract.rs`, `tests/samples/`, `RECEIPT.json`; workspace member; no `testing` feature (the P04 fake is a separate crate and independent of this one on purpose) | SEEN IN CODE (the `lico-png` layout) / PROPOSED |
| Version | `0.1.0`: the contract has not met a real server; it becomes `1.0.0` after the owner allows one check against a real loopback server. Semantic otherwise; in `0.x` a minor may break. | PROPOSED |
| Types | `Api { OpenAi, Ollama }`; `Message { System(String), User(String), Assistant { text, calls: Vec<ToolCall> }, Tool { call_id, name, content } }`; `ToolCall { id, name, arguments: serde_json::Value }` (always a JSON object); `ToolDef { name, description, parameters: Value }` (a JSON schema object); `Request<'a> { model, messages, tools, stream, context_tokens: Option<u32>, max_output_tokens: Option<u32>, include_usage: bool }` | PROPOSED |
| Encode | `encode(api, &Request) -> Result<Encoded, EncodeError>`; `Encoded { path, body }`; paths `/v1/chat/completions` and `/api/chat`; `EncodeError { EmptyModel, NoMessages, DuplicateTool(String), TooLarge }`; the body is at most `MAX_REQUEST_BYTES`; `CONTENT_TYPE = "application/json"` | PROPOSED |
| OpenAI request | `model`, `messages` (`role` system/user/assistant/tool; an assistant with calls carries `tool_calls: [{id, type: "function", function: {name, arguments: "<JSON text>"}}]`, its `content` null when empty; a tool message carries `tool_call_id` and `content`), `tools: [{type: "function", function: {name, description, parameters}}]` only when tools are given, `stream: true`, `stream_options: {include_usage: true}` when asked, `max_tokens` when given; `context_tokens` has no field here and is ignored | KNOWN FROM DOCUMENTATION |
| Ollama request | `model`, `messages` (an assistant's `tool_calls: [{function: {name, arguments: {object}}}]`; a tool message `{role: "tool", tool_name, content}`), `tools` as above, `stream`, `options: {num_ctx, num_predict}` when given | KNOWN FROM DOCUMENTATION |
| Decode | `Decoder::new(api, Framing)`, `Framing { Stream, Whole }`; `feed(&mut self, &[u8]) -> Vec<Event>`; `finish(&mut self) -> Vec<Event>`; `is_finished()`. `Stream`: OpenAI reads server-sent events (`data:` lines, blank-line separated, `\n` or `\r\n`, `:` comment lines ignored, `data: [DONE]` ends); Ollama reads one JSON object per line. `Whole`: the body is one JSON object, read at `finish`. One vocabulary for both. | PROPOSED (framing) / KNOWN FROM DOCUMENTATION (stream shapes) |
| Events | `Text(String)` (a piece of the answer), `Thinking` (at most once per answer, no content), `ToolCall(ToolCall)` (complete), `BadCall { id, name, raw (cut to 2 KiB), reason }` (a call whose arguments are not a JSON object), `Done(Done)`, `Error(StreamError)`; `Done { reason: StopReason { Stop, ToolCalls, Length, Other }, usage: Option<Usage { prompt_tokens, completion_tokens }> }`; `StreamError { Malformed(String), Truncated, TooLarge, Server(Failure) }` | PROPOSED |
| OpenAI stream | each chunk `choices[0].delta` with `content`; tool calls as deltas by `index` (`id` and `function.name` once, `function.arguments` in pieces to be joined, then parsed); `finish_reason` `stop`, `tool_calls`, `length`; a final chunk with `usage` and an empty `choices` when asked; reasoning in `reasoning_content` or `reasoning` (some servers); an in-stream `{"error": {...}}` | KNOWN FROM DOCUMENTATION |
| Ollama stream | `message.content`; `message.thinking` (reasoning); `message.tool_calls[].function{name, arguments (object)}` with no call id; `done`, `done_reason`, `prompt_eval_count`, `eval_count`; an in-stream `{"error": "..."}` | KNOWN FROM DOCUMENTATION |
| Call ids | A server's id is kept when it is at most 64 characters of letters, digits, `_` and `-`; otherwise, and for Ollama, the decoder makes `call_1`, `call_2`, ... in order (deterministic, unique in one decoder) | PROPOSED |
| Reasoning | Never in `Text`; the first piece of it makes one `Thinking`; its content is dropped (owner decision 5) | PROPOSED (owner decision) |
| Failure | `classify(api, status, body) -> Failure { kind, message }`; `FailureKind { KeyNeeded (401, 403), ModelMissing (404, or a not-found message), ToolsUnsupported (a 400 that says the model has no tool support), ContextTooLong, Busy (429, 503), BadRequest, ServerError (5xx), Unknown }`; `message` is the server's text with control characters removed and cut to 300 characters; the text rules are heuristics, an unknown text is `Unknown`, never a guess that acts | KNOWN FROM DOCUMENTATION (error body shapes) / PROPOSED (kinds) |
| Ollama facts | `show_request(model) -> Encoded` (`/api/show`); `read_show(body) -> Show { context_tokens: Option<u64> (a `*.context_length` of `model_info`), tools: Option<bool> (`capabilities` holds `tools`) }`; `None` when the server does not say | KNOWN FROM DOCUMENTATION / PROPOSED (owner decisions 3 and 9) |
| Limits | `MAX_REQUEST_BYTES` 4 MiB, `MAX_LINE_BYTES` 1 MiB (a stream line or event), `MAX_WHOLE_BYTES` 4 MiB, `MAX_CALL_ARGUMENT_BYTES` 64 KiB, `MAX_CALLS` 16 per answer (the loop's own, smaller, limits come later); the decoder holds at most one line plus the calls being built: about 3 MiB at most whatever the body size | PROPOSED |
| Invariants | **I1** any split of the same bytes gives the same events (one byte at a time equals the whole). **I2** `Text` is valid UTF-8 and never cuts a character (bytes of a split character wait for the rest). **I3** memory is bounded as above; beyond a limit: `Error(TooLarge)`. **I4** exactly one end: `Done` or `Error`, nothing after; `finish` on a finished decoder gives nothing; `finish` on a stream that ended without its end gives `Error(Truncated)`; a call is never given in a reply that is cut or fails: calls are given only together with the end, just before `Done` (a tightening found while building: the approved text allowed calls before a truncation). **I5** a `ToolCall` is given only whole, its arguments a JSON object; otherwise a `BadCall`; a partial call is never given. **I6** deterministic: no clock, no randomness. **I7** `encode` and `decode` never panic on any input; text survives the round trip byte for byte (escapes, emoji, Korean, control characters in a text are escaped, not lost). **I8** the text is raw: no cleaning, no trimming; cleaning is the adapter's. | PROPOSED |
| Errors | Wrong use is an `Err` of `EncodeError`, never a panic; a server's problem is an `Event::Error` or a `Failure`, never a panic | PROPOSED |
| Contract tests (`tests/contract.rs` for requests and names, `tests/reply.rs` for replies and failures, on samples I write by hand from the documentation, `tests/samples/*`) | encode: both APIs, with and without tools, with a tool round (assistant call then tool result), with `context_tokens`; decode: text, tool calls split over many chunks, parallel calls, reasoning, usage chunk, `[DONE]`, `\r\n`, comments, a whole body; **every two-way split and the one-byte feed of every sample equal the whole feed**; cut, malformed, oversize, too many calls, bad arguments, split multi-byte characters; failures (a table of status and body to kind); `show`; limits and public names pinned by tests that read the source (the lesson of the mutation check in M15-P03); a mutation check of my own tests before they count | PROPOSED |
| Pattern and budget | A plain new component: no port is needed (no upward edge exists); the default budget 256 MiB and 30 s, confirmed by `cargo xtask test lico-llm-wire --record` | PROPOSED |
| Not in it | HTTP, sockets, keys, the loop, the record, tool schemas of the program (the adapter turns the program's `TOOLS` table into `ToolDef`), text cleaning | PROPOSED |

Decisions taken with the approval (the recommended options): version `0.1.0` until a real-server check; `Thinking` as a content-free marker; a bad tool call becomes `BadCall` and the loop tells the model; the P04 fake stays independent of this crate so that the two implementations check each other.
