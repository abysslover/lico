## What was built

A person, or an agent with the person's yes, sends text, selected lines or a whole conversation from one session to another. Up to 4 KiB goes inline under a header the host writes; longer goes to a file in the receiver's own folder and the receiver gets a notice. Agents reach Lico through a tool connection served inside the host (no process per session). Steps in the order they were built; hashes are those of the branch after the replay onto main (step RB).

- **S01, S01c: what the real program does (AC-07).** Two probes with `claude` 2.1.310, no code of the product: 72 and 9 runs. A tool call held as a plain JSON reply is dropped at 60 s; a streamed one survives 4 min and is dropped at 300 s unless a per-server `timeout` or an environment variable lifts it; a message written during a running tool is queued at once and injected at the tool boundary of the same turn, with one `result`; pre-allowing `mcp__lico__*` makes Lico's approval the only prompt (12 of 12 asked nothing). Tables in the plan note.
- **Decision 1: no tool call is held open.** A tool that needs a person's yes returns `pending` at once; when the person decides, the host sends the outcome into the calling session as an input (origin `Host`, header `[from lico | time | approval ID]`). Reasons: the hold depends on limits that move between program versions; a hold that ends at its cap sends the model into a retry loop; a woken model does not poll. Cost: one extra turn per decision, only for the first of a kind (`keep` needs none after).
- **S02 `550957c`, `2a4b5cc`: the listener and the tools.** One loopback listener inside the host, bound at the first Claude session, `POST /mcp` only (JSON-RPC; Host and Origin checked; bearer required; 32 connections; 5 s deadlines; 128 KiB body; failed-credential throttle). A key per provider process (16-byte id, 32-byte secret, memory only), constant-time compare, revoked when that process ends. The config file (0600, in a 0700 folder) is passed with `--mcp-config` and removed at the first authenticated `initialize` (measured: the program does not read it again, `exp/202610/20261027/00001_config_file_after_connect`). Every Claude session also gets `--allowedTools 'mcp__lico__*'`. The loopback is exempt from the person's proxy (`NO_PROXY`). The live check used about 5 haiku turns.
- **V4 `960efbb`, N1 `e7873d8`: two gates before the transfer.** The `[agent] ` tag skeleton now removes format characters, marks and U+2800 (a generated table, Unicode 15.0.0: 358 ranges, 2,169 code points, with a Python mirror); a session name or account label that shows nothing is refused.
- **S03a `669b994`, `6127a45`, `22a1a76`: the transfer core.** Owner op `transfer.send` and `lico session send ID TEXT|- [--from ID2]`. Header `[from session 'NAME' (ID7) | HH:MM | message | SIZE]`; a body line that looks like a header is defused with a leading space (R2 `f0c0643` widened the rule to white space after the bracket and any case; the gate fix `35fd415` made the first character decide, see F1 in "The gate verifier"). Over 4 KiB the text is stored in the receiver's own inbox (`handoff/<receiver>/<date>/<time>_<from7>_<kind>.md`, 0700/0600, written under a temporary name and linked into place, the only `--add-dir` of that session), with the first three lines, a reading hint and, since `b7c60b1`, "The file can be removed after 30 days, or sooner: the handoff folders of all sessions together keep 256 MiB, and the oldest files go first." in the notice. Retention 30 days / 256 MiB, no timer. Receiver states: busy and waiting-for-approval are delivered (the program queues); disconnected is refused `session_disconnected` (Lico never resumes on its own); nothing is queued by the host. One log line per transfer, never the text.
- **S06 `409249d`, `c97411e`: the window.** "Send to session..." (Ctrl+Shift+S) with the sources draft / selected lines, the other sessions by number, the delivery line ("inline" or "as a file, nothing is cut") and Enter; the draft is cleared only on a reply of delivered. A received header is drawn dimmed with the name lit, only when the whole line is the header the host writes (styling of a record text; the boundary is the header the receiving agent sees).
- **S03b `626dc6c`, `62c547a`: `send` on the tool connection.** `from` is the token's session, never an argument. 20 calls a minute per caller (every `send`, `create`, `history` call counts, refused ones too); hop counter (`chain_depth`, `MAX_HOPS` 4; a person's input restarts it; a host notice leaves it alone); a request body over 128 KiB is refused `too_large` with the way out. Claude receivers only (decision 2).
- **S04a `b422738`, S04b `8490fc0`: the person's yes.** A pending record in memory (8 per session, 1 MiB of text over all sessions, 64 cards shared with the program's own, 12 h expiry with no timer) shows as a card: `send to 'NAME' (ID7) | SIZE, N lines | "first line"`. Keys Y/N after a dwell of 800 ms (R1 `fb261fb`; Shift+S needs Shift, R1b `a3185bc`; since `bdbee81` a click on Allow or Deny and the two menu entries wait for the dwell too), V reads the whole text in pages of 16 KiB (`approval.text`, `lico approval show SESSION N [OFFSET]`), Shift+S allows for the session (`keep` on `approval.answer`, `lico approval answer SESSION N allow|deny [--keep]`). Deciding performs the action with depth, rate and receiver state checked again, then the notice goes to the caller. Two sessions answering each other's sends from two threads finish within 5 s (no lock held across a decision). R4 `fbc9faa`: a `host_timeout` is told as "the host has not said yet", not "not answered" / "nothing was sent".
- **S04c `0c8fbac`, `d4565de`, `fb2ce5e`, `b185cd8`: `create`.** An agent asks for a new Claude session in the caller's folder, account, model and effort, mode `default` (never inherits "auto"); at most 4 alive per caller and 8 in all (`keep` never lifts them, decision 3); the card says model, effort and "starts at once on the account's allowance", and these words stay whole whatever name the agent gives. An agent's text is cleaned once, before the card, the pages and the receiver (`d4565de`).
- **S05 `12aad90`, `ed0b216`, `5475957`: the whole conversation.** "Hand over conversation..." and `lico session send ID --conversation --from ID2` read the provider's own record (a streaming, defensive reader; unknown types shown as `[record of type X not shown]`; the head says what was not shown and whether the program compacted its record) into one file in the receiver's inbox. It is a person's act only (no card, decision 6). It reads records of Claude Code 2.1.310 and 2.1.311 (decision 7; the layout of 2.1.311 was compared first, 2 model turns). A message that holds only a `thinking` block gets no heading and is not counted as shown.
- **S07 `318430b`, `d785052`, cap `a836187`: `history` and `read_handoff`.** `history` (last n records, at most 400 lines / 32 KiB) goes through the person's yes like `send`; `read_handoff` reads a file inside the caller's own inbox only (canonical path, no links, 32 KiB a part, no yes). The cap of the whole `tools/list` result went from 2048 to 4096 bytes before these two joined (decision 8); it is now 3,265 bytes.
- **Fixes of the early review (R1 to R4, V6 `3b71bd1`, R3 `7f0d370`), the owner's hands-on findings (H1 `8801594` the identity line `Lico 0.0.0 (commit ..., build ...)` in the window title, About, `lico --version` and the host-replacement notice; H3 `a6303a9` one sentence per refusal code of an input; H2 `a6a10e9` Enter in a disconnected session reconnects it and sends once; H4 `9d17dac` the echo across a resume pinned; H5 `6bef892` below), the flaky-test round (R5a `05d2dd9`, R5c `ff9c8f7`, R5b `f0237d6`, R5d `8cba86d`, R5e `c1e73a7`, R5f `2ae73e6`, R5g `a9c1aed`, R5h `c293249`, R5i `5407348`, R5j `f072857`, R5k `9e4a2f2`), the replay RB `fcb92b5`, R5l `9e7078c` / `29b251d` (the window waits for a dying host that still listens) and R5m `df94b77` (`read_log` skips a segment the host dropped).** One-line account of each in the plan note.

## Security

- **Approvals and per-receiver folders are consent and least privilege, not a sandbox (SF-08).** What Lico stops is unasked use of its own channel, and it shows and logs each use (SF-01, SF-03). A session whose program has permissions skipped (the default for new sessions) runs shell commands as the user: it can read any file of the user, the other inboxes and the token files included, and can run `lico session send ID --from ID2`. The spawn clears the environment (the program gets `PATH`, `LANG`, `NO_PROXY` and the home variables, no `LICO_SOCKET`), but an agent with a shell can compute the socket path. Through the command line `transfer.send` is a person's act: no card, no hop count, no 20-a-minute window applies. The header a receiver sees proves only that the host wrote it. The stance is that of the credential store and the key broker: a process of the same user can already do what this does. Nothing is built for it in P03.
- **The token and the config file.** Memory only; revoked with the process it was made for (the reader of a closed session cannot revoke a resumed one's key, tested with a lingering helper); the file exists about a second per start (and until the provider ends if the program never connects); a token string appears in no log, no `ps` line and no record. A server named `lico` in the person's own user settings gets the same pre-approval (`mcp__lico__*`; `--strict-mcp-config` is not passed on purpose).
- **The listener.** Burst 50 then 100 requests a second for the host, 32 connections, 5 s deadlines, 128 KiB body, head first, then Host and Origin (403), then the credential (401, or 429), then the rate, then the body; a refused credential writes one log line with the reason (never a credential), within its own budget.
- **An agent's text** is cleaned once (`leads::agent_text`: control characters, escape sequences, hidden and format characters, a Unicode 15.0.0 marks table), defused when a line looks like a header, and tagged `[agent] ` in the history when it looks like a lead; the person sees the same text on the card, in the pages and the receiver sees it. Over 4 KiB it is a file in the receiver's own folder, 0700/0600, read through `read_handoff` that checks the canonical path and refuses links.
- **Limits as written, F4 to F10 of the early review.** (F4a) 32 connections held with a slow head byte keep calls at 503 `busy` for the 10 s head deadline (a 2 to 3 s head deadline and slots for authenticated callers are in the register); (F4b) one bucket for the host, so a script looping on `sessions` starves the others (a bucket per session); (F4c) one session can fill the 1 MiB pending text with eight requests of about 128 KiB (a 256 KiB share; `pending.rs` is at 785 of 800); (F5a) chain depth counts hops since a person last wrote into the chain; it was counted per message, and since `b680610` it is the deepest count of the last ten minutes (`HOPS_MEMORY`, 600 s from when the count was last set or raised), so a third session's short text no longer lowers it, and A and B with `keep` can still pass four steps in each ten minutes while a third session nudges them (a design limit of AC-04, see F4 below); (F5b) the caps of `create` count from zero after a restart (`made_by` is memory, `session.rs` line 421): a session that is resumed counts again, but only inside one host process, and the sessions made before a restart are not counted after it (the verifier's run S6 f: one caller reached 8 running sessions after one restart, and 12 are possible after the next); `session.resume` is not held to the caps (a person's act), and each `create` still needs the person's yes; (F6) the retention sweep lists then removes by path, so a session writing its own inbox could swap a date folder for a link (same user, nothing gained), and the 256 MiB budget is global, oldest first; (F9) the marks table is pinned to Unicode 15.0.0 and a first line of only joiners shows an empty quote on the card while V shows the whole text; (F10) Y does not need the text to have been read, the notice names the inbox path in full, `keep` is keyed on the asker's session and the receiver's id (a renamed session stays covered, a replaced one is not), and the oldest `keep` is dropped silently at eight, after which the next send asks again.
- **Not checked by me, left to the gate verifier:** the lead's final security pass on the tip and the runs it wants.

## Try it yourself (for G3)

You need the `lico` file from the lead's build of the tip. Item 1 needs no sign-in; from item 2 on you need a Claude Code account (a real turn is billed by the provider). Everything runs on a private socket, so your own host is not touched; keep the socket path short.

```
T=$(mktemp -d)
lico host --socket "$T/host.sock" --state-dir "$T/state" --sessions 0 --producing 0 &
export LICO_SOCKET="$T/host.sock"
lico gui --socket "$T/host.sock"
```

1. **The build.** Help > About Lico prints `Lico 0.0.0 (commit ..., build ...)`; `lico --version` on the command line prints `lico 0.0.0 (commit ..., build ...)` with a small l. Check the commit is the tip you were told.
2. **Sign in and make two sessions** (Ctrl+N twice, names `api-server` and `docs`; Ctrl+A for the account).
3. **Send from the box.** Type a line in `api-server`, press Ctrl+Shift+S, pick `docs` (a digit or a click), Enter. The box empties; in `docs` the history shows a dimmed `>> [from session 'api-server' ...]` line with the name lit, then the text, and `docs` answers. A long text (over 4 KiB) says "as a file ... Nothing is cut." and `docs` gets a notice with a path in its own folder.
4. **Hand over the conversation.** Session > Hand over conversation..., or `lico session send DOCS --conversation --from API`. The window says before sending that the file may hold what the conversation held.
5. **An agent asks.** In `api-server` tell the model to send `docs` a short text with the `send` tool, to list the sessions, to read the history of `docs`, and to create a new session. Each makes a card in the bar (the buttons are dimmed for 800 ms and a click on them or on the menu entry does nothing until they wake, as the keys do; the program's own questions keep Y, N and the buttons at once): Y allow, N deny, V read all, Shift+S allow for the session (not offered for `create`). `lico approval show SESSION N` and `lico approval answer SESSION N allow|deny [--keep]` do the same from the command line. After a decision the caller gets a notice and carries on.
6. **Enter in a disconnected session** (close it with Ctrl+Shift+W first) resumes it and sends the text once. A session started by an older build has no tool connection until it is restarted.
7. **Clean up:** `lico --socket "$T/host.sock" host stop --force`, then remove `$T`.

The host and command-line parts were run on private sockets many times in the tests; the window steps are covered by the window tests and the captures, not run by hand in your window.
