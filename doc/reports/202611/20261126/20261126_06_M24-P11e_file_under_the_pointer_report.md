## 1. What the person sees (READ; MEASURED in the window test)

- A **file or folder name that is really there**, written in a conversation, is underlined while the pointer is over it, the pointer becomes a hand, and a click opens it in the window's file viewer (a folder as a list, a file as text; `path:12` opens it from line 12).
- A name that is not there (a missing file, a word, a web address, a version) is not underlined.
- What a click did before is unchanged anywhere else: a click in a block selects it whole and folds it, a drag selects and copies, Shift+click extends, a command card keeps its click.
- A file that is not text is shown by the viewer as such; nothing is handed to the system's program.

## 2. How it is built (READ)

- `gui/filelink.rs`: `names` (the detection, in bytes of the line's text), `resolve` and `probe` (where a name is and what it is), `State::ask` (the look on a short thread with 30 ms to answer, a table of 256 answers kept for 5 seconds, 16 looks out at most, a late answer taken by the next look), `State::frame` and `find` (the name under the pointer from the last frame's layout), `paint` (one pixel row under the glyphs of each row of the name), `file_link_click`.
- A hover is an overlay of the scroll step (`Overlay::selection`): the frame is drawn whole while a name is under the pointer. The scroll oracle runs with a name hovered at three scales.
- The viewer is the one the list of folders opens (`files_open_preview_from`, `files_open_at`); `files_preview_to_line` puts it at the line.

## 3. Checks (MEASURED)

- **The tests now**: twelve unit tests in `filelink_tests` (the detection of names, the Korean particle, where a name is, the look with its time bound and table, the name under the pointer in a laid-out conversation, the underline pixels at three scales, the wrapped name, the edges of rows and glyphs, the lines of the dump and the underline of a name on a later line, the ink in the dark and light themes, the click, the viewer's line) and the scroll oracle with a name hovered (one test at the scales 1, 1.25 and 2), 13 in all (written beside the code, not run red before it: the mutation checks below stand for that run); a window test (`tests/test_file_link_window.py`: names found, no hover on a missing name, hover and underline of a file and a folder, a click opens the viewer at line 12, a folder as a list, a binary file shown as such, a click beside a name still selects)
- **What the mutants found**: a surviving mutant (`paint: ink not toned`) led to a real fault: the underline was drawn in the ink of the text toned once by `tone_ink` and then toned again by `rect`, which tones every colour it fills with, so in the light theme the stretch came out as the dark theme's light gray on a white ground (almost invisible); the line that toned it is gone (`rect` does it once) and a test paints in the light theme and in the dark one with a coloured ink; other survivors showed code that could not change what is drawn and it was deleted (the second pass of the trimming of a name's end, two guards of the position after a path, the filter of the dump's names by the rows on the screen, the browser and terminal checks of `file_link_ctx` that a selected session already excludes, the clear of the selection and the redraw after a click, which opening the viewer does); the rest were closed by tests (a tab or a new line ending a name, an extension with a digit, a hidden file with no extension, a name in a bracket, the edges of a row and of a glyph, a pointer on the first character of a name, the underline of a name on a later line and of a name that wraps with a last row of one glyph, the replacing of a stretch by the next hover, the return of the move, the Call Room, the late answer and a dead look of the table, the exact last page of the viewer)

## 4. What is not decided (the owner's)

- The file opens in the viewer of the main pane (with the same close and back as a file clicked in the list on the left), not as a new tab in the bar above it: the bar holds sessions, calls, the browser and terminals, and a file tab would be a fifth kind with its own state and close.
- A session on another machine (ssh), a panel (the start page too), the browser and terminal tabs and the Call Room have no links; names with a space in them (`My Notes.md`) are not found; a relative name in a session that runs in a work tree is looked for in the session's folder only.
- A file that is not text is shown by the viewer and not opened by the system's program (a double click in the list of folders still does that).
- The viewer starts a few rows early at `path:12` when a long line above wraps (it counts the rows it shows).
