## 4. Found on the way (READ, MEASURED)

- **The suite is over the limit of `180 s`** also on a quiet machine (`227.0 s` at a load of `3`; the test build was `26.6 s` of it). At `0.8.1` it was over by `1.6 .. 8.4 s` at a load of `13` to `15`; now it is over by `25 .. 90 s`. The limit stays (the owner's); whether to raise it, or to cut the cost by splitting the modules so that finished ones are not tested again (the owner's M25 of 2026-11-26), is the owner's decision.
- **The test map was missing three window tests** (P11e, P11f, P11g): `tests/test_selection.py` is not selected by a change of the files of a phase (it checks the whole tree against the map), so the phases' hooks did not see it red. Fixed in the release commit; the lesson for the next phases is to list a new test file in `tests/testmap.toml` in the same commit.
- **A window test waited for the agent but not for its picture** (`tests/test_agy_tile.py`): it failed once when the machine's load went to `43`; the sibling tests already wait for the picture. Fixed in the release commit.
- **The first build after a version change peaks over the bound of `1,536 MiB`** (`1,655.9 MiB`; at `0.8.1` `1,550.1`): a rebuild of the whole crate. The bound stays; the commit that changes the version is accepted by the hook only after the suite has been run by hand once on the staged tree (the build is then skipped by hash).
- **The middle dot**: the owner's rule of 2026-11-26 says no middle dot in new or edited code and documents. P11c's pill copied the form of the tool call's pill (`▸ head  \u00b7 N lines`) and so drew one; it is `/` now (`c466657`). **Older code still draws it** (the pill of a tool call, the chat cards, the Call Room titles and the Home tab's prefix): untouched, as the rule leaves unmodified code; the two pills now differ in the separator, and whether to change the older ones is the owner's.
- The first cold run after a version change is the slowest (`230.4 s`, `152 s` of it builds); the others skip the build.
