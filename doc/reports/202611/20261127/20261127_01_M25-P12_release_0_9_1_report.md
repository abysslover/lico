## 4. Found on the way (READ, MEASURED)

- **The suite is over the limit of `180 s`** also at a load of `7` (`210.6 s`). The limit stays (the owner's); whether to raise it, or to cut the cost by splitting the modules so that finished ones are not tested again (M26), is the owner's decision. Every phase of `0.9.1` hit it in its by-hand run (`194.5 .. 281.3 s`) and was accepted by the hook (limit `300 s`), never by raising anything.
- **A by-hand run hit the limit of `300 s` three times**: P10's first run (the host's load was `14` to `16` from other users, no red test); P11's first run, inside the rebuild of `185 s` that a one-line clippy fix had made necessary (no test had begun; the lesson is to run clippy before the by-hand run); and P11's second run `281.3 s` ended with the guard's exit 3 because two whole-tree guards (the size ratchet `91.3 s` and the hidden-characters check `83.4 s`, which take `1.8 s` and `1.3 s` alone) were over their `15 s` budget at a load of `8` to `13`, with no red test. Nothing was bypassed: the same command was run again.
- **One red test in a component this release does not touch**: `lico-proxy`, `a_denied_port_is_refused_for_loopback_in_every_mode_and_a_public_destination_on_that_port_is_not_touched` (`components/proxy/tests/contract.rs`, the connection count of the test origin read right after a connect: `0` against `1`) failed in the first by-hand run of the version commit; the component's tests passed `35` of `35` three times alone and in the second run. It reads as a race (the origin counts the connection on its own thread), not a defect of the program; **it was not fixed here** (a release phase does not edit code, D4); a short wait for the count in that test is the owner's to ask for.
- **Build peaks over `1,536 MiB`**: P09's first run (`1,604.7 MiB`) and the test build of the by-hand run of the version commit (`1,749.9 MiB`); the build of the version change itself peaked at `1,268.6 MiB`. The bound stays; the recovery is the by-hand run followed by the commit with the receipts.
- **`pri-heavy` waited for memory** (pressure above `20 %` from other users) before P11's runs; it was waited out, never bypassed.
- **agy updated itself to `1.5.18`** between P08 and P09; the pin (the record, the simulator, the fixtures, the contract test) was made again after the test's own probe answered as the record says.
- **No hook was bypassed** and no limit raised.
