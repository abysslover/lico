## 2. Rendering path (item 2)

- **What the painter receives.** DOC/READ: the engine's render build paints its own pages and offers `Page.captureScreenshot`, `Page.startScreencast` with `everyNthFrame` and `maxWidth` parameters, `screencastFrame` events carrying `offsetTop`, `pageScaleFactor`, `deviceWidth`, `deviceHeight`, and `Page.screencastFrameAck`; `jpeg` appears in the binary's strings, so JPEG is at least one format (READ, not confirmed as the default). No draw list exists: **frames are images**. The painter therefore blits a decoded pixel rectangle into the window's existing `u32` buffer under the tab bar and above the status rows, like any other region.
- **Fit with the window.** The window already runs `ControlFlow::Wait` with a frame throttle of 100 ms while flooded (MEASURED in the code, `gui/mod.rs`). A frame event is an event like a host line: it sets "dirty" and one redraw follows; **no new thread that wakes when idle** is needed if the CDP socket is read by the one reader thread the host side already uses for sessions (a blocking read that wakes only for data). Idle tab with a static page: the engine sends nothing (ASSUMED; DOC says nothing), so Lico does nothing.
- **Lico-side bounds (COMPUTED).** One frame at 1200x800 is 3.84 MB as 32-bit pixels; the tab keeps at most two (the shown one and the one being decoded): 7.7 MB, bounded by the window size, and a hard cap of 16 MB (a request for a larger viewport is refused). A compressed frame is read with a 4 MiB cap. State per tab (URL, title, history of at most 100 entries) is a few KiB.
- **Cost per frame.** NOT MEASURED (the engine was not run). ASSUMED to measure in the first build phase: bytes per frame, decode time, latency from input to paint, at 1200x800 and 640x560. Decoding is Lico's cost: **Lico has no image decoder** (MEASURED: its dependencies are winit, softbuffer, cosmic-text, unicode-linebreak, x11rb, serde_json and the lico components; `lico-png` writes PNG only and its reader exists only under the test feature). A baseline JPEG decoder is about 700 to 900 lines; a PNG reader (inflate and unfilter) about 350, and the test support already holds one that can be promoted. If the engine can send PNG frames, take PNG first.
- **What will not render (DOC, the project's own list):** long-tail CSS, some Web APIs, media playback, compositor effects, platform font rasterisation; no service workers; IndexedDB not persisted. Fonts come from `--font-dir`; Korean text needs a Korean font in a directory handed to the engine (ASSUMED: the system font directories are not scanned; to test).
- **Not verified, and the question I could not answer:** whether a loopback test page paints at all, and how usable it looks. That is the first thing to measure, and it is the decision gate of the next phase (section 7).

## 4. Security (item 4)

- **The page is untrusted data.** No Lico operation, tool, session, handoff or clipboard operation is reachable from it: the engine gets no Lico socket, no Lico token and no Lico environment; the only thing that flows from the engine into Lico is frames and a few event fields, parsed by the fake-tested CDP component with size caps and never evaluated or executed; title and URL are cleaned like any other text from outside before they are drawn.
- **What the engine process can reach, and how it is limited without a namespace (MEASURED here):** `unshare` and bubblewrap do not work on this machine (item 1 of the owner page). **Landlock ABI 4 works**: a small launcher inside Lico (the host already calls `prctl` and `setsid` directly, `procs.rs`) restricts the child to read-only access to the system library directories and the engine's own directory, read-write to one empty scratch directory, and TCP connections to the one CDP port plus, when the owner opts in, the one developer port; everything else (the home directory, `~/.claude`, `~/.codex`, the keyring socket, Lico's sockets) is denied by the kernel. Not covered by Landlock ABI 4: UDP (DNS) and abstract Unix sockets (ASSUMED to need a seccomp filter or to be accepted as a residual risk; to decide). Also: cleared environment (only a minimal `PATH`, no `HOME`, no `DISPLAY`, no `DBUS_*`), an empty working directory, `PR_SET_PDEATHSIG`, its own process group, a memory limit with `prlimit`, no inherited file descriptors. **Residual risk, said plainly:** it is a third-party program running as the owner; Landlock is the main wall.
- **CDP.** DOC: loopback bind by default; `OBSCURA_CDP_TOKEN` is a bearer token sent in an `Authorization` header (optional on loopback); non-loopback binds need 32 bytes. Lico binds loopback only, generates a 32-byte token per engine start from the system random source, gives it to the engine through its environment (the one place the engine reads it; it is on no command line and never on disk; `/proc/PID/environ` is readable by the same user only) and sends it in the header; the port is chosen by Lico (whether `--port 0` or a free-port probe works is NOT KNOWN).
- **Network from the engine.** TLS verification on (DOC: rustls in the render build; whether any switch turns verification off was not checked, and Lico would never pass one); the private-network block stays ON by default (DOC: `--allow-private-network` or `OBSCURA_ALLOW_PRIVATE_NETWORK`): a page on `localhost` for developers needs an explicit per-tab opt-in that Lico turns into that flag for that engine start, off by default; `--proxy` never used; `OBSCURA_PROXY`, `OBSCURA_STEALTH`, `OBSCURA_PROFILE`, `OBSCURA_ROTATE_PROFILE` are removed from the environment by the clearing.
- **No stealth, in Lico.** Lico never passes `--stealth`, never sets `OBSCURA_STEALTH` or the profile variables, and the specification will say that Lico uses and exposes no anti-detect feature. **READ finding:** the plain build carries those surfaces anyway (owner page, item 4), so "the engine is run in its plain form" means "no switch is turned on", not "the code is absent".
- **Logging.** The host logs: engine started or ended, the exit code, the port never, the token never, the page URL's host only (no path, no query), no page content, no frames.
- **Supply chain.** The engine is installed by the owner from the release page and checked against the pinned SHA-256 that Lico shows in its message; Lico never downloads it and never runs one whose hash is not the pinned one unless the owner says so in a setting.
