## First screen: what the fence does not close, in plain words

The engine ran inside a Linux fence (Landlock) that denies every file except the allowed ones and every TCP connection except two ports. **The fence does NOT close** (each is pinned by a test of `lico-sandbox`, so a kernel that starts to cover it makes a test fail):
1. **Abstract Unix sockets.** The owner's X server listens on one, and so may other services. A hostile engine could connect to such a socket even though it has no `DISPLAY`: the cleared environment hides the name, it does not stop a guess.
2. **UDP** (DNS lookups, datagrams to loopback or beyond).
3. **Signals to other processes of the same user** (the engine could kill the owner's programs), and `/proc` of other processes (the policy never opens `/proc`).
4. CPU use and the number of processes it starts.

**What the engine actually tried (READ from `strace -f -e trace=network,openat,open,execve,bind,listen` of the whole run; signals were not traced, so item 3 is not observed either way):** one `execve` (the engine itself; `obscura-worker` was never started); sockets of one kind only, `AF_INET` TCP: one listening socket on the CDP port and six connections, all to `127.0.0.1` on the fixture's port; **no** `AF_UNIX` (abstract or by path), no UDP, no `AF_NETLINK`, no name lookup; 343 `sendto` calls, all on accepted CDP sockets (none with an address). Opens that the fence DENIED (`EACCES`): `/proc/self/maps` (6 times), `/proc/self/cgroup`, `/proc/stat`, `/proc/sys/vm/overcommit_memory`, `/sys/devices/system/cpu/online`; the engine ran normally without them, so the fence was **not widened**. Opens that succeeded outside the engine's directory and the system libraries: `/dev/urandom` (allowed). So in this run the engine did none of the things the fence does not close; that is what it did, not what it could have done: the residual risk is real and is the owner's to know.

## Does anything contradict the aim?

No. A page a person would call usable rendered, and the engine can be driven over loopback as planned. Four things to decide in the re-plan (details below): (a) **identity**: the page sees a Windows Chrome `143` by default, not an honest browser; Lico can set the user-agent string but not the platform; (b) **fonts**: Korean needs a font directory handed to the engine (without one it paints boxes); (c) **flow control**: the screencast needs an acknowledgement per frame; (d) **no composition events**: committed Korean text works through `Input.insertText`, the pre-edit cannot be shown inside the page.

## What follows for the plan (for the lead; the numbers decide, not guesses)

- **Frames: take PNG first.** Sizes are about the same as JPEG (animated 28.9 KB against 24.7 KB; still 69.6 KB against 60.2 KB), the engine's CPU per frame is about the same (16 against 14 ms), and a PNG reader (inflate and unfilter, about 350 lines, the test support of `lico-png` already holds one) costs less than a JPEG decoder (about 800 lines) and is lossless. A JPEG decoder stays an option for photographs.
- **`DEFAULT_MAX_MESSAGE`: set from a figure.** The largest frame seen was 69,612 bytes; the raw size of a 1920x1080 frame is 8.3 MB (COMPUTED) and a compressed one is a fraction of it (ASSUMED: under 2 MB for a busy page). Propose 4 MiB for the tab, with the error `TooBig` shown as "a frame was too large", in place of 8 MiB.
- **One reader, an acknowledgement per frame:** the host adapter acknowledges each frame after it has taken it, which also paces the engine; a tab that is not shown stops the screencast (no frames, no work).
- **Identity:** accept with the specification sentence and add: Lico sets the user-agent string to an honest one with `Emulation.setUserAgentOverride` and says in the tab's help that the page may still see a Windows `platform`; or ask the project; or choose another engine. For the owner.
- **Fonts:** Lico hands the engine a font directory that holds a Korean font (the system's, found by Lico, read-only in the fence); without one the tab shows boxes, so a missing font is a visible message in the tab.
- **Korean input:** commit-only in the page through `Input.insertText` (it works), the pre-edit in the address field only: as decided.
- **Developer pages on `localhost`:** the switch is an environment variable at engine start: per-tab means an engine start per opt-in, or one engine for opted-in tabs: a design choice for P05.
- **The fence:** `lico-sandbox` as built, the confinement above; abstract Unix sockets, UDP and signals remain open (first screen). Whether that is acceptable for a product that runs a third-party engine with the owner's privileges is the owner's decision; a stronger wall (a seccomp filter against `AF_UNIX` and UDP, a dedicated user) is not available without more than std and was not tried.
