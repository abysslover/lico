# Owner end-to-end guide (`lico 0.8.2`)

Version: 1.35.0

This guide is for the account owner administering Lico on Linux. Lico never reads a provider's login files and never stores a provider secret in plaintext; application-owned credentials live only in the OS keyring (`lico cred`, failing closed when the store is locked or missing), and each account owns a private directory (`0700`) that the provider itself populates when you sign in. A live provider session may incur provider usage charges.

State lives in `$XDG_STATE_HOME/lico` (or `~/.local/state/lico`), and the local owner-only socket defaults to `$XDG_RUNTIME_DIR/lico/host.sock`. Everything ships in one self-contained executable (`lico`): `lico gui` opens the administrator window, `lico host` runs the background session host, `lico --version` prints the build identity, and `lico licenses` prints third-party notices.

## Browser tab (`lico 0.5.0`, M17)

A browser tab shows a page with the Moli engine (since `0.7.0`; the engine of `0.5.0` to `0.6.2`, Obscura, is gone). The first time you open a tab the engine installs itself, with no question (from `0.5.1`; you asked for this in the chat): the tab says "installing the browser engine" with its size (about 46 MB), the source and the start of its SHA-256, then starts it and loads your page; `lico browser open` waits and says so. It needs the system `curl` and `tar` and a network. The engine is one pinned release (Moli `v1.1.25`, held by the component `lico-engine`, which also says how many patches of Lico's are on it: none yet); the install is one file, `moli`, in `~/.local/share/lico/browser/moli-v1.1.25`, checked against its SHA-256 before it runs. If the install fails the tab says why, and the manual way is the fallback: the answer of `lico browser open` and `lico browser list` carries the address of the release archive, the SHA-256 of the archive and of the file `moli`, and the folder (take the file `moli` out of the archive's folder and put it there; every directory and file yours and not writable by others). `{"auto_install": false}` in the owner-only file `browser.json` of the state folder turns the self-install off. Then `lico browser open https://SITE`, `lico browser list`, `lico browser shot b1 FILE`, `lico browser close b1`, or, in the window, the browser icon of the toolbar (`Session > New browser tab`; `Session > New local browser tab` is a tab that may reach services on this machine only, and nothing else). Since `0.8.0` the **address bar** is at the top of the tab, with `‹`, `›` and `⟳` (back, forward, reload) before the field, and a new tab is an empty page with the bar focused: type an address or words and press Enter. `F1` shows the help; `Ctrl+L` goes to the bar, `Alt+Left`, `Alt+Right` and `F5` go back, forward and reload, `Ctrl+W` closes. The engine runs only while a tab is open, and its idle memory is about 75 MiB (Obscura's was 215). Since `0.6.1` the page looks alive, and since `0.8.0` without a header and without a ring on your last click: the pointer is a crosshair over the page, the bar follows the page when you have not edited it (an address too long for it is cut in the middle, so that the site and the end both show), and the one row at the bottom of the tab says what the header said, where typing goes (the page after a click on it, the bar after `Ctrl+L`) and the Korean you are composing while the page has the keys. The engine sends the picture of the page as JPEG (quality 90; since `0.7.0`, `lico-frame` reads JPEG as well as PNG): a page of 1920 x 1200 is about 130 KB a frame and not 3.8 MB, which is what makes a large window possible. `lico browser shot` still writes a PNG. What Moli does that Obscura did not (measured in the real window, 2026-11-17): Google search opens (the old engine was sent to Google's "unusual traffic" page), Korean paints in a single-line `<input>` as well as in a `<textarea>`, boxes made with `contenteditable` take typing, and a text cursor is drawn. Known limits: the page may still see a Windows platform (`navigator.platform` is `Win32`, the engine decides that), while its user agent names Lico and Moli; the engine's control socket has no password (Moli has none; it listens on this machine only, and the sandbox and the guard are what keep a page from it, so another program of yours could drive a tab: a token is planned for a build of our own, `M21`, and waits for your word); mouse moves reach only the element under the pointer; a page that uses all the memory it is given ends the engine (the host stays, the next `browser.open` starts it again); the engine needs `fontconfig`, a CA bundle and a Korean font on the machine, which Lico passes to it. There is no stealth setting any more: Moli has none, and an old `"stealth": true` in `browser.json` is read and ignored (you said Lico can use stealth, and this holds for an engine that has it; the lead removed the setting with Obscura and asks you to confirm). The folder of the old engine, `~/.local/share/lico/browser/v0.2.6`, is not used and is not removed by Lico: delete it when you like. **Words typed in the bar are searched** (since `0.8.0`): text that is not an address (several words, or one word that is not a host name; `docs.rs` and `https://example.com` still load that address) goes to the engine of the setting `browser_search` in the owner-only `browser.json` of the state folder, an `https` address with one `%s` where the words go, for example `{"browser_search": "https://html.duckduckgo.com/html/?q=%s"}`. With no setting the engine is Google, `https://www.google.com/search?q=%s`: one measured probe of three engines (2026-11-19, the real engine, the same query with a Latin and a Korean word) opened Google, DuckDuckGo's html page and Bing, each with real results and the Korean intact, and Google was chosen as the default; DuckDuckGo's html page and `https://www.bing.com/search?q=%s` are the two to write in the setting if Google stops answering. A setting that is there and wrong (not `https`, no `%s`, or two) is refused with `search_setting` in the window and nothing is loaded: it never falls back to Google, so that a mistyped setting cannot send your words somewhere you did not choose. The command line (`lico browser open`) and a local tab take addresses only and never search. No engine is promised to work: a search can end on the site's "unusual traffic" check page, which the engine cannot pass; then write another engine in the setting, or open the site's own home page and type the search into its box.

**The tab remembers the pages it has shown** (since `0.8.0`): the address, the title and the time of at most 100 pages, newest first, in the owner-only file `browser_pages.json` of the state folder (a page is kept once it has loaded; a tab for this machine's own services leaves nothing, and a damaged or group-readable file reads as an empty list). An address is kept without the part after `#`, and a page whose address carries a secret by name (a query name with a word such as `token`, `code`, `key`, `password`, `sig` or `session`, or a path parameter such as `;jsessionid=`) is not kept at all; a secret in the path of a link, or under a name not on that list, cannot be told from the page's own name, and `Clear remembered pages` removes whatever is kept (a page that routes by its `#` part reopens at its start). `[ Chats ]` lists them among the chats, with the browser's picture and the page's title (the address when it has none), and a click on one opens it in a new tab. The group `Browser pages` of the menu `More` has `Reopen closed tab`, which opens the newest remembered page that no tab shows (asked again, the next one), and `Clear remembered pages`, which removes the file and says how many pages it held. The host's `browser.reopen` and `browser.forget` take no address from their caller: an address comes into a tab only from this list.

## Terminal tab (`lico 0.8.0`, M23)

A terminal tab is a shell of yours in a tab of the window, beside the sessions and the browser tabs. It is not a session: it has no account and is not in `[ Chats ]`. Open it with the **Terminal** picture of the new-session wizard (a shell at once, no step after it; since `M24-P04` the line `Session > New terminal tab` is gone); it starts in the folder `Directories` (the left side) shows when that folder is on this machine, else in the folder of the session in front, else in the last folder the window kept, else in your home (since `M23-P03d`: the left side decides, also while a session is in front; since `M23-P04d` also when the left is on **Home**, because Home only highlights a row and `Directories` goes on listing a folder: that listed folder counts, and the same folder is where the **agy** picture starts `agy`). The shell runs as you and is **not fenced**: it can do whatever you can do in any terminal. It is given a short list of the host's variables, not the host's whole environment (since `M23-P09`): where things are and who and what language you are (`PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `LANG`, `LANGUAGE`, `TZ`, `TMPDIR`, every `LC_*`, every `XDG_*`), the display and the input method (`DISPLAY`, `WAYLAND_DISPLAY`, `XAUTHORITY`, `DBUS_SESSION_BUS_ADDRESS`, `DESKTOP_SESSION`, `XMODIFIERS`, `GTK_IM_MODULE`, `QT_IM_MODULE`), the ssh agent (`SSH_AUTH_SOCK`), your editor and pager (`EDITOR`, `VISUAL`, `PAGER`), the names that point the shell at your own start-up files (`ENV`, `ZDOTDIR`, `INPUTRC`) and the address of Lico's own socket (`LICO_SOCKET`; no other `LICO_*`). A key or a token that the window was started with (a launcher's, or one exported for another program) does not reach the shell, so it does not reach an agent in it; what your own start-up files (`~/.bashrc` and the like) export is yours and is there as in any terminal. A program in the shell runs as you and can find Lico's socket by its usual path, so taking the address away would not keep it from the socket: what an agent may do is its own permission setting's. Keys go to the shell first; the window keeps **Ctrl+Shift+C** (copy), **Ctrl+Shift+V** and **Shift+Insert** (paste), **Ctrl+Shift+W** (close the tab) and **Shift+PageUp**, **Shift+PageDown** and **Shift+End** (the history); **Ctrl+Tab** and the other **Ctrl+Shift** letters go on to the window. When `claude`, `codex` or `agy` runs in the shell (it is the program in front of the terminal), the tab shows that program's small picture where the text `>_` was, and `lico terminal list` and the host's `terminal.watch` say `agent` (`claude`, `codex`, `agy` or null; since `M23-P04a`). The host only reads which program is in front of the shell (read-only: nothing is sent to the program and none of its screen or conversation is read), so what the program may do stays its own settings' (Lico's approvals belong to the sessions Lico starts, not to a program you start in a terminal). A tab that is not in front is not watched and keeps the picture it last had until you open it again. The conversations you had with `agy` (the file `agy` keeps of the prompts typed in it, `~/.gemini/antigravity-cli/history.jsonl`, read only when it is yours alone: no group or other permission, not a link; the first prompt of a conversation is its title, the last folder it ran in and the last time are its place and time) are cards in `[ Chats ]` with `agy`'s picture (since `M23-P04b`); a click opens a terminal in that folder (at the home when the folder is gone) and types `agy --conversation` and the conversation's number into it, as you would, so you see what runs; a terminal the window opened that way and that still shows `agy` is shown instead of a second one. Lico never starts `agy` with its flag that skips permissions. A conversation you resumed by hand in a terminal is not known as that terminal's. A shell that ends closes its own tab (a short note says so only when it ended with an error or a signal). At most 8 terminals are open at once; closing a tab sends the shell's process group a hangup and, after a second, a kill, and no shell outlives the host. The host holds the pseudo-terminal and the emulator (the component `lico-vt`); the window only draws the grid. From the command line: `lico terminal open|list|close|send|show [--text]|resize`.

## Administrator window (`lico gui`)

1. **Start, maximized launch, and host continuity**: `lico gui` opens maximized on the active monitor by default (`lico gui --windowed` opts out to standard `1280x820` windowed sizing) and starts `lico host` automatically if none is running (and replaces an older host build cleanly while reconnecting existing sessions). Closing the window or pressing **Esc** on an empty input line detaches the view without stopping running sessions.
2. **Accounts, SSH remote targets, and sign-in (`Ctrl+A`)**:
   - **The screen is pictures** (since `M24-P03`): the list is a card for each account (the provider's picture, its label, an orange star on the default one and a disc, green, orange or red, for what is left of its quota: red under 5 percent, orange under 20) and a card with a plus for a new account; a click on a card is the number key, a click on the plus is **A**. An account's page is five pictures in a row, the size of the new-session pictures: a **key** (sign in), a **pencil** (rename), a **star** (make it the default), a **bin** (remove it, its sessions stay unbound) and a **bin with a cross** (remove it and end its sessions, named `Wipe`); the bin that was clicked once is lit and says `Sure?` until the second click. Every key below works as before: the lines of text are under the pictures, and the sentences that say what a removal would do and what the provider answered stay as text.
   - Press **A** to add a local or SSH remote account: **Tab** toggles provider (`codex` or `claude`), and **Up** / **Down** (or clicking the target row) chooses `local (this machine)` or any explicit host alias discovered from `~/.ssh/config` (`[ssh: <host>]`). SSH remote accounts run `claude auth login` / `codex login` directly on the remote host over `BatchMode=yes` SSH inside an isolated `0700` remote `$HOME/.local/state/lico/accounts/<id>/{home,<provider>}` so the remote host connects directly to its LLM API provider without copying tokens to the local machine.
   - Press `1..9` to open an account's actions: **S** signs in with the provider's own flow (**Ctrl+C** / **Ctrl+Shift+C** copies the URL, **Ctrl+O** opens it in the browser, **D** selects Codex device-code sign-in; any verification code typed or pasted into the input line is masked as `*`, sent once, and cleared immediately without logging).
   - **F** sets the default account for that provider; **R** renames the account label in place without touching credentials or account homes; **D** removes the account while keeping its sessions unbound; **E** removes the account and ends its sessions (both ask for a second press after naming bound sessions).
3. **New sessions (`Ctrl+N`)**:
   - The plus icon of the toolbar, **Ctrl+N** and `File > New session` open the **new-session wizard** (**Ctrl+Shift+O** opens the whole one-page form at once, every row the wizard shares out over its steps: since `M24-P04` it has no line in the `File` menu). Step one is five pictures: **Claude**, **agy**, **Codex**, **Local LLM** and **Terminal**; Claude and Codex are grey while you have no account (the person icon of the toolbar is lit then and opens `Accounts`). **agy** is not a session of Lico's, so it needs no account: it is lit when a program named `agy` is found on this machine (in a folder of the window's `PATH`, or in `~/.local/bin` or `~/bin`; looked for each time the wizard opens) and grey with the sentence "agy is not installed on this machine." when not. **agy** and **Terminal** have no step after them: each opens a terminal at once in the folder Directories shows, and **agy** types the plain word `agy` and Enter into it, as you would (never its flag that skips permissions), so the terminal tab shows its picture (see the terminal tab). **One touch** (since `M24-P02`): a click, Enter or Space on **Claude**, **Codex** or **Local LLM** starts the session at once, as the rows of the next steps would have it: the account is the provider's default (else its first), the folder is the one `Directories` lists on this machine (else the one the form kept; a **Home** session has none), the name is the host's, and the model, the effort and the permission are left to the program's own settings (Lico asks for a model or an effort only when you chose one; the permission is the one you used last). The steps stay for what cannot be answered by itself: no account yet (the picture is grey and says so), a Local LLM with no server known, an account on an ssh host (a folder of this machine is no folder of that host), or a folder that is not valid; and a start that the host refuses ends on step two with the reason. **Shift with the click, or Shift+Enter, is the old way**: step two is the account and the folder (for Local LLM, the server), step three the options and Start. Steps two and three show their choices as boxes, not as text rows: the account (its pictures, then `+ New account`), the model, the effort, the permission and the worktree are small boxes in one row with the chosen one filled; the recent folders, the model servers, `Sign in`, `Back`, `Next` and `Start session` are boxes of their own (a box that cannot be taken yet, such as `Next` with no valid folder, is dim and says why). A click on a box does what the keys did on its row, and the keys (Tab, Up, Down, Left, Right, Space, Enter, Esc) work as before; the folder, the branch and the name are typed, so they stay text. A second click on `+ New account` while it is chosen goes on to adding the account. **Ctrl+Shift+N**, the house icon and `Session > New Home session` open the same wizard for a **Home** session, which has no folder.
   - The wizard (and the one-page form) asks for the provider, a local or `[ssh: <host>]` account (or create one inline), permission mode (`auto` skips routine tool prompts; `default` asks on each gated action), optional model/effort, working folder (`Folder`, supporting `~` / `~/...` on SSH remote hosts and reading `CLAUDE.md` without trusting repo-local `.claude/settings.json`, `.mcp.json`, or `.codex/config.toml`), and optional local git worktree branch (`Worktree`, creating an isolated branch checkout for local repositories).
4. **Two-pane workbench, horizontal session & Call Room tabs (Home sessions, `⇄ A·B`), left `[ Directories ]` | `[ Chats ]` sidebar, bottom telemetry bar, and daily session control**:
   - Open sessions and shared inter-session Call Rooms (`⇄ <Label A>·<Label B>`) live in a horizontal **Tab Bar** across the top of the right chat pane (the row has no buttons of its own since `0.8.0`: the toolbar's icons and the `Session` menu open sessions; a **Home** session (**Ctrl+Shift+N**) is folder-less, for quick ad-hoc questions, and its tab starts with `H·`; `×` closes or deletes a tab, and `<`/`>` or mouse wheel scrolls overflow tabs; a Call Room two sessions share has its own tab, and each of its two session tabs carries a small `⇄` mark after its caption, a click on which opens the room), while the **Left Sidebar** (**Ctrl+B** collapses/expands) provides two tabs (the `[ Calls ]` tab is gone: rooms are for the agents that talk to each other, and `@AgentName` in a prompt and the agents' tools still start them): `[ Directories ]` (topped by a persistent `<` / `>` Back/Forward navigation toolbox across directories and pagination pages — **Alt+Left** / **Alt+Right** or mouse Back/Forward buttons — plus a `☆`/`★` bookmark toggle and `Marks (N) v` quick-jump popup persisted in `settings.json` across restarts; local and `Host: <ssh> v` directory tree, gold `★` active `cwd` highlight + `-> active` jump-back pill, the `Home  lico://home` row above the path row (the virtual directory of Home sessions), instant filter, `.dot` toggle, pagination, and wide inline UTF-8 file preview where **Esc** returns straight to chat), and `[ Chats ]` (one list of every past session of this machine, whatever directory the other tab shows, newest first, with full `offset`/`limit` pagination and zero top-N truncation: one card for each, with the provider's picture, the title (two lines when it needs them), a time coloured by its age, the folder on the second line (`lico://home` for a Home session) and a state picture, a green, orange or red disc for a chat that is open in a tab (by its memory), a ring for a closed tab and a square for an ended one, while the state words, the account and the id are in the hint row; a click resumes the chat or shows its tab and moves `Directories` to the chat's folder, or to Home; the pages the browser tab has shown are listed among the chats, see the browser tab). **A card shows what was said** (since `M24-P08`): its title, its count of turns and the transcript shown when you resume the chat leave out what a program wrote for you, not what you typed: the markup that Claude Code keeps of a slash command and of its output, the notices of background tasks and of teammates, and the sentence Orca types into an agent's terminal (`You have 1 orchestration message. Run ...`). That holds for the chats of Claude, Codex and `agy`. A slash command you typed with words after it stays, as the line you typed (`/orchestration fix the bug`), and is never a title; a command with no words (`/model`) says nothing and is not shown. A chat of nothing else is titled with its provider and the start of its id (`claude (3f2a91bc)`). A chat of a machine reached by ssh is titled the same way, but its list is read by a script on that machine that still takes the first record as it is, so its title falls back to the provider and the id instead of the first real question.
   - **`+ New chat`** (its own row above `[..]  parent directory` of the `[ Directories ]` tab, for the shown local or ssh directory; greyed with the reason when the host is unreachable or Home is shown: `Home has no folder: open a directory first`) opens a small centered dialog: choose an account (Up/Down, or click; the default is marked), then `Resume` (default) or `New` (Left/Right, or click). `Resume` shows `Last Session : <provider> / <YYYY-MM-DD HH:MM> / <title> (<N> turns)` for that directory and account (`?` when the turn count is not known, as for ssh chats) and, on Enter, continues that chat (a tab that already holds it is shown again); with no earlier chat it says so and opens a new one. `New` starts a fresh auto-mode conversation. `Options...` (or `o`) opens the full new-session form for the same directory; Esc closes the dialog.
   - **Right-click menu of `[ Directories ]`** (`0.8.2`, M24-P10a): the right button over the list (the folder and file rows, `[..]`, the empty space under them; not the tabs, the filter or the buttons) opens a small menu at the pointer, kept inside the left column. Its lines, in this order: **Open terminal** (a terminal tab in the folder you pointed at) and **New folder** (asks a name on the input line, as renaming a session does, so the Korean input works; Enter makes the folder inside the folder you pointed at and the list shows it; a name that is empty, has a `/` or a line break, is `.` or `..`, is longer than 255 bytes or is already taken is refused with its reason and stays on the line to be corrected; nothing existing is overwritten; Escape makes nothing). A folder row means that folder; a file row, a link and the empty space mean the folder the list shows. Up and Down move over the lines, Enter runs the selected one, Escape or a click anywhere else closes the menu (the click goes no further). On an ssh host every line is greyed with `this machine only`; with no folder listed `no folder here`; New folder is greyed `close the open screen first` while another screen is open, and a click on a greyed line says why. Two more lines (`M24-P10b`) work on the **row** you pointed at: **Rename** (the old name is on the input line; Enter renames it in place; a name that is empty, bad, the same as now or already taken is refused with its reason and stays on the line; nothing is ever replaced; Escape renames nothing) and **Delete** (a question first: it says the name and what it is, such as `a folder with 12 items` (counted up to 5,000, then `more than`), `a file of 1.5 KiB` or `a link to ...`, and that it cannot be undone; there is no Trash; **Y** deletes, **N** or Escape keeps it; a folder goes with everything in it, and a link, also one inside a folder, is removed as a link: what it points to is never touched). On the empty space both are greyed `point at a file or folder`; on the root, your home folder and every folder above it they are greyed `protected` (a link that points at one of them is only a link and may be renamed or deleted); while another screen is open they are greyed `close the open screen first`, like New folder. The last two lines (`M24-P10c`) work on the row too: **Extract** (on a file whose name ends in `.zip`, `.tar`, `.tar.gz`, `.tgz`, `.tar.bz2`, `.tbz2`, `.tar.xz` or `.txz`, capitals too, and on a link to such a file, which the list shows as the file) makes a new folder beside the archive named like it without its ending (`photos.zip` makes `photos`; a taken name takes the first free `photos 2`, `photos 3`; nothing is replaced and nothing is written outside the new folder) and **Compress** (on a folder, a file or a link) makes `name.zip` beside it (a taken name takes `name 2.zip`; nothing is replaced; a link inside a folder is stored as a link and never followed). They run off the window's thread, so the window stays usable: the flash says `Compressing name...` and then `Compressed: name.zip` (or `Not compressed: why`), `Extracting name...` and then `Extracted: name` (or `Not extracted: why`), and the list shows the result. **One archive is made at a time**: while it runs the two lines are greyed `an archive is being made` and the other lines of the menu stay usable; a run longer than 30 minutes is stopped and what it made is removed. Extract lists the archive first and refuses it, with the reason and with nothing written, when a member has an absolute name or a `..` part, is a link (symbolic or hard), a device or a pipe, when there are more than 100,000 members, when a name has a line break or another control character, or when the sizes add up to more than 8 GiB (the sum is the listing's own: an archive whose listing lies is beyond what `unzip` and `tar` can tell, said in the report); a failure in the middle removes the folder it made. So an archive that holds a link is refused, also one that Compress made of a folder with a link inside (it can be opened by hand). An archive that holds one top folder is extracted as it is, so `photos.zip` holding `photos/` gives `photos/photos/`. The tools are the system's own `zip`, `unzip` and `tar`, run with a list of arguments (no shell), a cleared environment, no input and the folder of the row; their error text is read up to 4 KiB and shown in one line. When one is not installed its line is greyed (`zip is not installed`, `unzip is not installed`, `tar is not installed`); Extract on anything else is greyed `not an archive`, and on the empty space both lines are greyed `point at a file or folder`. These two lines ask no question, so an open screen does not grey them.
   - **When each line was written** (`0.8.2`, M24-P11a; the first of the phases that give the conversation a time on every line): the host now notes the second at which it wrote each line of a session, and the window asks for it. Nothing was drawn for it in that phase (the next bullet draws it). The times are kept as **runs**: a run begins only when the second changes, so a burst of a hundred lines in one second costs 16 bytes, and they are in an owner-only file beside the log folder (`<log folder>.times/<session>.times`, folder `0700`, file `0600`), not in the log, so a build that does not know the file still starts and the lines of the protocol (`[sequence, text]`) do not change. A session made before this version has no times for its old lines (the log never had them), which is shown as nothing; its new lines are timed. A time never ends a session: a file that is missing, torn, linked or unwritable means no time and is said once on the host's error output; a deleted session's file goes with it, and the start of the host removes the files of sessions that are not registered. The request is `stamps` (`session`, `from`, `until`: the run that covers `from` and every later run that begins before `until`, at most 2,048; read-only; an older host that does not know it answers `unknown_op` and the window asks again no sooner than ten seconds later). The window asks about once a second, **one request at a time**, newest lines first, at most 2,000 lines to a request, and only for the lines its view holds and does not know yet, so a view that is complete asks nothing; its state dump has `times` (the range, the number of runs, the first and the newest time, the requests asked and answered).
   - **The time beside each block, and a colour for who spoke** (`0.8.2`, M24-P11b): on a window wide enough (the text area has at least 70 columns, in the form that fits: see the next bullet) every block of the conversation stops short of the right edge, and in the room that is left, to the right, stands **when it was written, to the second** (`2026-11-25 14:03:07`, the local time of the machine that shows it), in a dim grey at the first row of the block. A block is a run of lines from one speaker: your own lines (a multi-line message of yours is one block), a message from another session, the agent's reply, or a command or tool with its output (a card of its own each time); a note of the window (an event that is shown, an error) is a block each. The first line on the screen also carries a time, so the reply you are reading keeps one when its first line has scrolled off (it then shows the time of the line that is at the top). ## Local model sessions (`lico gui`, `lico session create --kind local`)

A model server on this machine (an OpenAI-compatible one or Ollama, on a loopback address) can be a session of its own kind, next to Claude and Codex. Claude and Codex keep their own sign-in and are never sent to a local model.

1. **Make one in the window.** `Ctrl+N`, pick the **Local LLM** picture (in the one-page form, **Ctrl+Shift+O**, choose `local` on the Provider row with Left or Right). Nothing is looked for by itself. On step two, press Enter (or Space, or click) on the Server row: Lico looks once, read-only, for model servers on this machine and lists them; Left and Right choose a server, then a model; Enter on the Name row or on Start makes the session. The server of the last local session is offered again when the form opens. `+ New chat` offers the same server as one more row (`Local: MODEL at ADDRESS`); it always starts a fresh conversation (a local session is resumed from its tab).
2. **Make one from the command line.** `lico session create --kind local --endpoint 127.0.0.1:11434 --api ollama --model NAME [--context N] [--name NAME]`. The address must be a loopback address; `--api` is `openai` or `ollama`.
3. **A key, if the server wants one.** The window says so when it lists such a server. Store it with `lico local-key set ADDRESS:PORT` (the key on standard input, never as an argument) and scan again; `lico local-key clear ADDRESS:PORT` removes it. The key lives only in the OS keyring. There is no masked key entry in the window.
4. **What the session does.** The host itself asks the model server and keeps the conversation in an owner-only record; it runs Lico's tools for the model with the approvals every session has (a tool that needs one leaves its card and the turn waits for you). It has no access to files or a shell. The tab letter is `L`, the header reads `Local | MODEL | state`, and a notice says when the server takes no tools ("text only") or when the oldest turns are no longer sent to the model. Close ends the work and keeps the record, resume reads it again, purge deletes it.

## Memory guard (M19-P01, 0.6.0)

Requested by the owner in the chat, 2026-11-17. The session list shows each session's memory (the whole process tree, as RSS); the figure is orange when its largest process holds 400 MB and red from 500 MB, and the line under the list takes the worst colour. A click on a red session asks once whether to end it and resume it (the conversation resumes; tool jobs that were running are lost); `Y` does it, `N` keeps it. `lico session close ID` and `lico session resume ID` do the same by hand. The owner-only file `memory.json` in the state folder sets `warn_mb`, `limit_mb`, the automatic close (`"auto_close": true`, off by default: only idle sessions, never while you type, not twice in ten minutes) and the main agent that is warned (`"main_agent": "SESSION ID"`; `"warn_main": false` turns the warning off). Details: after the warning to the main agent the automatic close waits two minutes (and, while a main agent is marked and could be warned, until the warning has been tried, five minutes at most); when the whole machine runs low on memory (under 20 percent available: orange, under 10: red) the line under the list starts with the free share ("free 8% ...") and a session you start then is followed by a plain warning; with the automatic close on, a red machine also closes and resumes the heaviest idle session that is not the main agent, one every two minutes; after an automatic resume the session shows "[memory N MB: closed and resumed automatically]". A working session that shows no activity for ten minutes turns the line under the list orange and the hint under the mouse says when it last did something (`"stall_min": 10` in minutes, or `"stall_s"` in seconds; 0 turns it off). Known gaps: if the host restarts between the guard's close and its resume the session stays closed (resume it by hand); `main_agent` is only set in the file.
