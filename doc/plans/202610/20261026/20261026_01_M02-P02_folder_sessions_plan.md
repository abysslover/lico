## Goal

The basics people expect from agentic-coding tools, before any memory work: a session runs in a real folder the user picks, is created from one screen, can be closed, renamed and deleted, the input box takes a real (long, multi-line) prompt, and each session row shows its memory at the right end. Done means it works in the real window (captures), one test of the main path per slice, and one measured memory number. Memory and speed are recorded, not gated, except the two stops: idle window RSS >= 50 MiB and a leak.

## Settled points (the open questions of the task)

1. **Where the state lives.** Everything stays in the host's registry directory (mode 0700; files 0600, replaced atomically, as `sessions.json` is today). Each session record gains optional fields: `cwd` (absolute, canonical), `scratch` (bool), `name` (rename), `model` and `effort` (what was chosen, so a resume uses the same). The ten recent folders are a new file `recent_folders.json` in the same directory (`{"folders": [...]}`, newest first, canonical paths, written by the same atomic helper). It is updated only when a session with a chosen folder was created; nothing sends it anywhere, and the window gets it by asking the host.
2. **Migration.** There is no rewrite step. A record without `scratch` counts as scratch with `cwd = workspace_root/<id>` (exactly where it ran), a record without `name` shows the provider/account text as now. A field that is present but of the wrong type stops the load with a reason, like every other field of this file. The first save after the upgrade writes the new fields. An older host reading a newer file ignores the fields it does not know (it would look for `workspace_root/<id>`, which does not exist for a chosen folder: harmless).
3. **WK-06 by construction.** The delete code never takes the path to remove from the record. It checks the id against the session-id format (`s` and sixteen hex digits) and only then computes `workspace_root/<id>`, and removes it only when `scratch` is true, only when that path is a real directory (no symlink) and a direct child of `workspace_root`. A session in a chosen folder creates nothing in `workspace_root` and nothing there is removed for it. The three `remove_dir_all` sites in `core.rs` call one function of the new module (`folders::remove_scratch`), which shrinks `core.rs` by the three lines it replaces.
4. **Model and effort (SX-02).** Found out from the installed program, not hard-coded: the host runs `claude --help` once (the configured binary, no account, no network, 3 s limit, again when the binary's modification time changes) and reads two entries: the effort levels from the parenthesised list after `--effort` (here: low, medium, high, xhigh, max) and the model aliases from the quoted words after `--model` (here: fable, opus, sonnet). The screen offers "default" (the flag is left out) plus what was found; a full model name is accepted by the CLI (`--model NAME`, `[A-Za-z0-9._-]{1,60}`) but is not offered, because the program does not list full names. If the help text no longer has these entries the screen offers "default" only and says why; there is no built-in fallback list. Codex offers "default" only in this phase. Permission: the window says "Skip agent prompts" (stored `auto`, today's default) and "Ask" (stored `default`: the program's prompts come to the window's approvals through the prompt tool that is always on today). Sessions started before this keep what they have.
5. **Rename (SX-06)** is the record's `name` (<= 60 bytes, no control characters, empty = back to the default text), set by a new op `session.rename` and published in the session list and status entry, so every attached window and the CLI see it on their next update. It changes nothing the agent sees.
6. **What the window does today with an over-long draft** (looked at with a real window and the simulator on a private display; probe kept in `private/`): a 600-byte draft + Enter: the host refuses (`valid_text`, 512 bytes), the draft returns to the input box and nothing is said. A 5,000-byte paste + Enter: the request line is over 4,096 bytes, the host answers `too_large` without an id and closes the connection; the draft is gone and nothing is said (window and session survive, a new connection is made). Neither case is acceptable; IN-06 fixes both by checking the limit before sending and saying why.

## S02 — host (IN-01 first)

IN-01: one constant `MAX_INPUT_TEXT = 64 KiB` is the only text limit for `input`; `ipc::valid_text` keeps its 512-byte rule for every other field, and for `input` allows `\n` and `\t` but no other control character. A request line carries the text JSON-escaped, so the worst case is three times the text (an astral character escaped as two `\u` units is 12 bytes for 4); `MAX_REQUEST` and the HTTP `MAX_BODY` become 256 KiB, derived from the constant in one place, and a line over them still answers `too_large` and closes. The window, the CLI (`input` takes the text from the command line or stdin) and HTTP all go through the same check, and the window calls it before sending (S03). Then, in a NEW module `folders.rs` (validation, recent list, scratch removal, the `claude --help` reader), come: `session.create` with `cwd` (CLI `session create --cwd DIR`), the checks of WK-02 (absolute, <= 1024 bytes, no control character, exists, is a directory, can be listed, and is neither equal to nor inside - canonical paths, symlinks resolved - the registry, log, accounts and credential directories, `workspace_root` or any folder under it) with the reason in the reply, the record fields, `current_dir` for both providers (Claude `current_dir`; Codex `cwd` of `thread/start` and `thread/resume`), resume refused with the reason when the folder is gone (WK-04), `session.options` (models, efforts, recent folders) and `session.rename`. Core changes are limited to wiring (dispatch lines for the new ops, the three delete sites); the logic lives in the new module. `core.rs` is held by the size ratchet and may not grow: the dispatch lines add lines and the three delete sites give a few back, and where the net is positive I cut something else out of `core.rs` into `folders.rs` in the same commit; the allowlist number is not touched (a new entry needs the owner's word). A new host module keeps files small and reviewable; it does not shorten the daily run, because the test selection follows `crate::` uses transitively and a module that `core` calls is selected as `core` is (see the daily run cost note of 2026-10-26); only `gui/*` and `cli`-like modules are cheap. Tests (protocol, no display, `tests/test_folders.py`): a 20 KiB multi-line text reaches the Claude simulator and the Codex fake intact (byte for byte, newlines and tabs included); a 64 KiB + 1 text is refused with a reason and the connection stays usable; a session created with a folder runs in that folder (the simulator reports its working directory), its delete leaves the folder and its files untouched while a scratch session's folder goes; a missing folder gives no session; a chosen folder inside `workspace_root`, and one reached through a symlink into it, are both refused with the reason (otherwise deleting another session's scratch folder would remove the chosen folder's files, although WK-06 is right about the session being deleted); an id that is not in the session-id format is never joined to `workspace_root`. A folder that contains these directories (a home folder, say) is allowed: it is a legitimate choice and nothing in a chosen folder is ever deleted. `--add-dir` for the handoff folder is not added now (the folder arrives in P03): WK-05 holds in `default` mode because the program itself asks about anything outside its working folder and the prompt tool brings that to the window; P02 records this and tests nothing more. Risks: the echo of a long input in the history (decided, see S02b; the report states what the user sees for a 64 KiB input, with a capture); a bigger line buffer per connection (at most 256 KiB, only while a line is being read; the connection cap holds).

## S02b — the host echo of an accepted input (SC-10 moves from P03 to P02; decided by the lead, 2026-10-26)

A sent input must not vanish after Enter, in any window, after a restart, for any kind of session, and the host has to record inputs for SC-10 (a receiving session shows an answer with no question) anyway; a window-only echo would be thrown away and show the line twice once both existed. So the host appends the echo when it accepts an `input` (valid request, delivered to the provider or the agent, once per request id; a retried id and a refused input echo nothing), for synthetic, Codex and Claude sessions alike. Rules: every echo record starts with `>> ` (history records have no kind field and the protocol does not change; the prefix is the marker and nothing may depend on it for correctness; `> ` is already a tool-result line of the Claude adapter, `$ ` a command, `[` a note, so no other kind may begin with `>> `); at most `ECHO_LINES = 12` lines and `ECHO_BYTES = 2048` bytes of line text (newlines not counted), cut at a line boundary, or on a character inside the first line when that line alone is over the cap; then one marker record when anything was left out, with exact counts of the original text and saying the agent received it all (`>> [N more lines, B bytes not shown; the agent received all of it]`, or `>> [a long line is cut after K bytes; N more lines, B bytes not shown; ...]`, the `N more lines` clause left out when none is left), never silent. Each shown line passes the same `sanitize` as every other record (tab to space; bidi controls and the separators U+2028/2029 removed), so a person's text, and from P03 on the text another session sent, does not reach the log raw; the agent still receives the original bytes. The full text is not kept in the host log: the provider's own record holds it and SC-07 builds the whole conversation from there; one input costs at most 13 of the 2,048 retained records. The echo is appended right after a successful delivery, under the same session lock: no agent line can come in between, and a delivery that fails (`busy`) echoes nothing, so a retry cannot double it; an id older than the 1024 tracked ones would echo again, as it would be delivered again. The code is one function (`echo::append`, in the new module `echo.rs`, called from `Session::record_input`, the one place where an accepted input is recorded) so that P03 can add the `from <name>` header for text sent by another session in one place; the header is not built now. Tests: Rust unit tests of the fold (line cap, byte cap, character boundary, exact counts) and `tests/test_input_echo.py` (three kinds, a retried request id, a refused input, a 64 KiB multi-line input = 12 lines + one marker, a 64 KiB single line = one record <= 2 KiB + marker, still there after a host restart and read by the CLI `history`). Existing tests that compare history exactly change in the same step and are named in the commit message.

## S03 — window: the input box (IN-02..07)

A NEW module `gui/editor.rs` holds the draft as text plus a cursor (byte index on a character boundary), a pure state machine: insert, newline, left/right/up/down, Home/End, word movement, Delete, Backspace, Ctrl+Backspace, Ctrl+K, Ctrl+U, history recall, and the limit check. The window feeds it the keys it already receives and the composed text from the input method, so Hangul composition keeps its current path (preedit shown at the cursor, committed text inserted at the cursor); `gui/mod.rs` and `gui/ui.rs` only call it, and the draft code in `send_draft` and the draft map move out of `gui/mod.rs` into it, so the big files shrink. Enter sends, Shift+Enter inserts a newline; the box shows up to 8 lines and scrolls inside; a paste is normalised first (CR and CRLF become LF, a tab stays, every other control character - an escape from a terminal, say - is dropped and one line under the box says how many), the 64 KiB check applies to the normalised text, and a paste that would pass it is refused whole with the reason. Over the limit, or refused by the host, the draft stays and one line under the box says why (IN-06, including the case of today's silent drop). Up on the first line recalls earlier sent inputs of that session (kept in memory in the window only, not on disk); drafts and history are per session. The window's idle RSS is the hard limit, so the recall history is capped: 20 inputs per session and 256 KiB in all sessions together, the oldest sent input dropped first; the user sees only that Up reaches back less far, and nothing that was sent is lost because the transcript has it. A draft is never dropped (unsent text is the one thing the transcript does not have): it is one per session and at most 64 KiB, and the idle RSS is measured with realistic drafts. Tests: unit tests of the editor in Rust (movement, deletion, word jumps, limit; this is where the exhaustive checks belong) and ONE window test on a private display: type, Shift+Enter, move, edit, paste a long multi-line text, see the box grow and scroll, send it, and see it arrive intact; the Korean composition test of the suite keeps running unchanged. The window draws the echo the host gives (S03 adds no echo code beyond the failed-send case; `pending_inputs` stays only to return a refused text to its draft), and may style `>> ` (text a person sent) apart from `> ` (tool output), `$ ` (a command) and `[` (a note). The CLI stdin path (`text_from_stdin`) normalises CRLF and a lone CR to LF as the paste does, with one test, because `lico session send ID - < notes.txt` on a file with Windows line ends is plausible. Risk: the box takes more rows from the output area; the dump carries the geometry so the click boxes of P01 are checked at scale 1 and 2.

## S04 — window: the new-session screen (SX-01..03)

A NEW module `gui/newsession.rs` draws and handles one screen: folder (text field with the recent list below it, a click or Up/Down + Enter picks one; empty = scratch), name, account, model, effort, permission, Start. It replaces the Provider/Account/Label/Ready steps of the new-session flow in `gui/panel.rs` and uses the shared controls of P01 (`gui/controls.rs`); rows are a list of fields, so the "git worktree" row of P06 is one more entry. The last used values are the defaults and are kept in the host (the same record that the recent list lives in, so nothing is stored in the window). Start is greyed with its reason while the folder is not valid; a refusal by the host (WK-02) is shown on the screen with the host's reason and no session appears. No Tab completion of directory names in the folder field now (scope; the report says whether it deserves a slice in P06). Reachable by Ctrl+N and the menu as today. Tests: ONE window test: open the screen, pick a recent folder, choose model and effort from what the simulator's help lists, Start, and see the session in the folder (row shows the folder name, the dump shows the values); plus the missing-folder reason. Risk: the screen must fit at scale 2 in the default window size; the dump's geometry check covers it.

## S05 — close, rename, delete (SX-04..07)

A new host op `session.close` stops the agent and leaves the record resumable (state `disconnected`, as after a host restart; resume works as today and with the same folder). The window asks "stop and close?" only when the session is working; delete (existing `session.purge`) asks for a confirmation, then the log and, for scratch sessions only, the scratch folder go. Rename is F2 and a double click on the row, an edit line on the row with Enter/Esc. Each action is on a menu entry (Session menu, with its shortcut, greyed with its reason when it cannot act), a shortcut (F2 rename, Ctrl+Shift+W close - not a bare Ctrl+W, which readline users press to delete a word and would stop an agent by habit - and Ctrl+Delete delete) and a CLI verb (`session close|rename|delete`), so every action has all three (SX-07 asks for two). The confirmations are drawn by the shared controls in a NEW module `gui/confirm.rs`. Tests: ONE window test of the three actions (close a working session, rename it and see it in a second window, delete it and see that its scratch folder is gone and a chosen folder is not), plus one protocol test for `session.close`/`session.rename`.

## S06 — memory per session (MI-01..06), after the POC-0 D1 verdict

Not started before the lead's verdict on which number (RSS or PSS, agent only or the whole tree) is used. Planned shape: a NEW host module `memory.rs` walks `/proc` for the agent's process and all descendants every 3 s and only while a window is attached, writes the figure into the status entry, and the window draws it at the right end of the row (a NEW `gui/memrow.rs` for the formatting and the colour: 1 GiB and 2 GiB), plus one total line at the list's bottom (sessions, host, window). Measured and written down: the cost of looking (10 sessions: host CPU with and without a window attached, window RSS growth) and idle window RSS at scale 1 and 2 against 23.6 / 34.6 MiB. Test: ONE test that starts a simulator session that allocates a known amount and checks the figure within a stated tolerance.
