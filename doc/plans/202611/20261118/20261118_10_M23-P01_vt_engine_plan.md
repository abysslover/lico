## What this phase builds

The part of a terminal that is only logic: **bytes a program writes go in, a grid of styled cells comes out; keys, a paste and the mouse go in, the bytes for the program come out.** It is a new component under the component rules (`components/vt`, crate `lico-vt` 0.1.0): std only, no `unsafe`, no thread, no file, no clock, no environment variable, a spec first (`components/vt/SPEC.md`, written before the code), contract tests per public name and per invariant, a receipt next to it. The pty, the child process, the host operations and the window are the next two phases; nothing here touches the host or the window.

Why a component of its own: it is the largest piece of new logic of M23, and it can be tested thoroughly with no display and no process (feed bytes, read cells), which is where a terminal's bugs are. The pty needs `unsafe` calls to libc and does not belong in a pure component (the frame decoder has no `unsafe` either).

## The contract in short (the whole text is `components/vt/SPEC.md`)

| Part | What it does |
|---|---|
| `Term::new(cols, rows)`, `feed(bytes)`, `resize`, `take_reply` | the emulator; any cutting of the byte stream gives the same state; an answer the program asked for (cursor position, device attributes) is taken out with `take_reply` and written to the program's input by the caller |
| `Cell { ch, fg, bg, attrs }`, `Color`, `Attrs` | what the screen holds; a wide character (Hangul, CJK) is two cells, the left one with the character and the right one a tail |
| `view(scroll)` | the rows to show at a distance from the bottom of the scrollback, with the cursor and the total, so the window asks only for what it draws |
| `text_between(a, b)` | the text of a selection, trailing blanks cut, lines that wrapped joined |
| `modes()`, `title()`, `generation()` | what the program switched on (cursor keys, bracketed paste, alternate screen, cursor shown, the mouse), the title it set, a counter that moves when something shown may have changed |
| `encode_key`, `encode_paste`, `encode_mouse` | the bytes for the program: the keys with the cursor-key mode, Ctrl, Alt, Shift, the function keys; a paste wrapped as the program asked and made safe; the mouse as the program asked (X10 or SGR) |

What it understands (the rest is ignored, never an error): the C0 controls (bell, backspace, tab, line feed, carriage return, shift in and out); the escape sequences for save and restore cursor, index, next line, reverse index, set tab, full reset, the keypad modes and the two character sets (ASCII and DEC line drawing); the CSI sequences for moving the cursor, erasing, inserting and deleting characters and lines, scrolling and the scroll region, tab stops, the repeat, the device status and device attributes reports, set and reset mode (insert, origin, auto-wrap, cursor shown, alternate screen 47, 1047 and 1049, the mouse 1000, 1002, 1003 and 1006, bracketed paste 2004, the cursor keys 1), and SGR (bold, dim, italic, underline, blink, inverse, hidden, strike, 16 colours, the 256 palette, true colour in both the semicolon and the colon form); OSC 0, 1 and 2 (the title); the strings DCS, SOS, PM and APC skipped to their end.

## Decisions (the lead's defaults; the owner may change any)

| # | Decision | Why |
|---|---|---|
| D1 | No reflow of lines when the width changes: a row is cut or padded, and the program, which gets the new size, redraws | what a plain terminal does; reflow is a large piece of logic that the shells and the agents' screens do not need (they redraw on a size change) |
| D2 | A zero-width character (a combining mark, a joiner, a variation selector) is dropped, not attached to the cell before it | a cell holds one `char`; Korean text from the keyboard arrives as whole syllables, so nothing the owner types is lost; a later version may add it |
| D3 | The scrollback is bounded by cells (600,000), not only by lines (2,000 by default), and its lines are stored without their trailing blanks | a wide window must not hold 40 MB for a long session; the memory guard of the host counts the whole process |
| D4 | A pasted text has its escape characters removed when bracketed paste is on, and the end-of-paste marker cannot be written by the text | otherwise a pasted text could end the bracketed paste and run what follows as typed commands |
| D5 | The answer to a device-attributes request is a plain VT100-with-options answer (`ESC [ ? 62 ; 22 c`); the program's other queries (the version, the colours, the keyboard protocol) get no answer | a program that asks and gets nothing times out and goes on; an answer that is wrong is worse |
| D6 | The emulator knows no font and no pixel: `Color::Indexed` and `Color::Default` are for the window to turn into its palette | the palette is a look, and the look is the window's |
| D7 | Past `MAX_PARAMS` (32) parameters the later ones are dropped **with their digits** (found by a mutation check: the digits of a dropped parameter had been joined to the 32nd) | a sequence with more parameters than any program writes must not change the meaning of the ones that are kept |

## Steps (tests first; each is green before the next)

1. [x] **The spec**: `components/vt/SPEC.md` (the API, the invariants, the limits with their reasons, the list of contract tests) and the manifest (`Cargo.toml` with `[package.metadata.lico]`), the workspace member, the testmap row.
2. [x] **Contract tests** (`components/vt/tests/`): text and wrapping at the right edge (the pending wrap), the controls, the cursor moves and their limits, save and restore, erase with the current background, insert and delete of characters and lines, the scroll region and the scrollback, SGR in every form, wide characters (fit, no fit at the last column, overwriting half), split input at every byte of a sample stream and of a UTF-8 text gives the same state, invalid UTF-8, the alternate screen and the cursor it restores, the modes and the replies, the OSC title with both terminators and its bounds, the skipped strings, resize, the selection text, the keys, the paste and the mouse tables.
3. [x] **The invariants as tests**: it never panics (random bytes in random chunks, every single-byte change of a long sample stream, extreme sizes, a resize after every few bytes); after every step the cursor is inside the screen, every row has exactly the width, a wide cell is followed by its tail and a tail follows a wide cell; the memory bounds hold (the scrollback in cells, the title, a string with no end).
4. [x] **The code** (`components/vt/src/`: `lib.rs` the API, `parser.rs` the state machine and UTF-8, `grid.rs` the screen and the scrollback, `csi.rs` the sequences, `keys.rs` the keys, `width.rs` the width of a character; each under 800 lines).
5. [x] **Mutation checks** on the contract tests (at least 25 deliberate breaks of the code, each caught, the file restored each time); `cargo xtask check`, `verify`, `graph`, `test` for the component and its receipt; the whole `cargo test` of the workspace for what it touches; the commit with the guard on (the owner approves the prefix `phase/M23-P01-` through the question at commit time).

## Results (2026-11-18)

- The component `components/vt` (crate `lico-vt` 0.1.0): `SPEC.md` first, then the tests, then the code: `parser.rs` 389 lines, `csi.rs` 299, `grid.rs` 449, `term.rs` 233, `keys.rs` 220, `types.rs` 129, `width.rs` 45, `lib.rs` 35 (each under 800). Std only, no `unsafe`, no thread, no file, no clock.
- Tests: 106 (`contract` 25, `keys` 15, `screen` 56, `invariants` 10), written before the code. The first run of the code failed one test, and that test was wrong (it read the scrollback total after switching to the alternate screen); no code fault came from the tests of the first run. The invariants run the sample stream cut at every byte, every single-byte change of it, random bytes in random chunks with a resize between, extreme sizes and the memory bounds.
- Mutation checks: 78 deliberate breaks over `parser`, `csi`, `grid`, `term`, `keys` and `width`; 65 were caught at once, 13 survived the first run and each got a test: an overlong `E0` form, a printed DEL, a parameter over 65535, the 33rd parameter, an empty scroll region, a palette index of 256, an erase to the end of a row that left the wrap mark, a scrollback that kept the blanks of short lines, the byte limit of the plain mouse form, and the borders of three width ranges. All 78 are caught now and every file was restored byte for byte after each. One of the 13 was a real fault (D7): the digits of a dropped parameter joined the 32nd; fixed.
- Gates: `cargo xtask check`, `graph` (the one cycle as before, 210 modules), `test lico-vt --record` (106 passed, peak 20.2 MiB of 256, 1.2 s of 30) and `verify` pass; `cargo clippy -p lico-vt --all-targets` is clean (6 warnings fixed); `tests/test_selection.py` (35) passes with `lico-vt` in the set of components that a build input of the binary runs.
- The changed-files suite: adding a workspace member changes `Cargo.toml`, which is a build input of the binary, so it selected all 558 tests in 117 files. Two runs each failed one different window test that passes alone (`test_first_view.py`, 15.5 s against its 15 s guard; `test_everyday_comfort.py`, a notification race): both while another build loaded the machine, none touches the new crate. The third run was green (117 files skipped by receipt). The commit hook, which gives the suite 300 s, refused the first commit attempt for that reason; the suite with receipts has to be run before a commit that changes `Cargo.toml`.
