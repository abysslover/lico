## What this phase builds

The host side of a terminal, with no window. A new module `terminal` of the host (`src/host/hostd/src/terminal/`), registered through the driver port exactly as the browser is (`driver::register_ops`; the hubs never name it): a table of at most 8 terminals; each one is a **pty** with a **shell** in its own session and process group, and a `lico_vt::Term` that the pty's output is fed to (D2 of the milestone: the pty and the emulator live in the host, so a shell survives the window closing and a second client sees the same screen). The seven operations, and `lico terminal` on the command line that builds them, so that everything can be tried and tested from a shell with no window.

## The contract in short

All operations are **socket only** (D1): `POST /v1` answers them `bad_request`, as for `subscribe` and `clipboard.write`, and no MCP tool names them.

| Operation | Request (besides `op`, `v`, `id`) | Reply |
|---|---|---|
| `terminal.open` | `cwd` (absolute folder, checked as a session's folder is; default: the person's home), `shell` (absolute path of an executable; default `$SHELL` when it is absolute and executable, else `/bin/sh`; see D9), `cols`, `rows` (1..=500, 1..=200; default 80 x 24) | `tab` (`t1`, `t2`, ...), `pid`, `cwd`, `shell`, `cols`, `rows` |
| `terminal.list` | none | `terminals`: `tab`, `cwd`, `shell`, `pid`, `title`, `cols`, `rows`, `running`, `exit` (null while running; the code, or 128 + the signal), `started` (unix seconds); `max_terminals` |
| `terminal.close` | `tab` | `closed: true`; the shell's group gets `SIGHUP`, and `SIGKILL` after one second if it is still there; `unknown_tab` |
| `terminal.input` | `tab`, and exactly one of `text` (UTF-8) or `data` (base64): at most 64 KiB | `written` (bytes); `terminal_ended` when the shell has ended; `busy` when the pty took nothing for 2 seconds; `unknown_tab` |
| `terminal.resize` | `tab`, `cols`, `rows` | `cols`, `rows`; the pty's size is set (the kernel sends the window-change signal to the foreground group) and the emulator is resized |
| `terminal.watch` | `tab`, `seq` (the change number the caller has; `0` is answered at once), optional `scroll` (rows up from the bottom, default 0) | `seq`, `cols`, `rows`, `title`, `cursor` (`[row, col]` or null), `modes` (`app_cursor`, `app_keypad`, `bracketed_paste`, `alt_screen`, `mouse` as a word, `mouse_sgr`, `focus_events`, `cursor_visible`), `scroll`, `top`, `total`, `lines` (see below), `wrapped` (one boolean per line), `bells`, `running`, `exit`; the call waits (no timer) until the change number is above `seq`; `unknown_tab` when the terminal is gone (closed, or the host stopping) |
| `terminal.text` | `tab`, `from`, `to` (each `[line, col]`, absolute: 0 is the oldest line of the scrollback) | `text` (the selection as the emulator reads it) |

**Lines** are runs: one line is an array of `[text, fg, bg, attrs]`; a run is the cells that share a style; the right half of a wide character adds nothing to `text` (the width of each character is `lico_vt::char_width`, which the window has); the trailing blank cells in the default style are not sent. A colour is `-1` (the default), `0..=255` (indexed) or `256 + (r << 16 | g << 8 | b)` (true colour); `attrs` is `Attrs::bits()` (bold, dim, italic, underline, blink, inverse, hidden, strike).

**The shell** runs as the person, in the person's environment, **not in the host's fence** (Q3 of the milestone). It starts with the pty as its input, output and error, as the leader of a new session with the pty as its controlling terminal, the signals that a host may have been started ignoring at their default action (D12), and `PR_SET_PDEATHSIG` so that no shell outlives its host.

## Decisions (the lead's defaults; the owner may change any)

| # | Decision | Why |
|---|---|---|
| D1 | The terminal operations are in `SOCKET_ONLY_OPS` | a shell is a command line as the person: whoever holds the HTTP token of `POST /v1` must not get one; the socket is the person's own files and permissions |
| D2 | The shell's environment is the host's, **without** every `LICO_*` variable (the host's own settings and the id of a session) except `LICO_SOCKET`, and with `TERM=xterm-256color` and `COLORTERM=truecolor`; Lico adds no credential of any kind (it has none in the environment: they are in the keyring) | Q3 of the milestone; `LICO_SOCKET` keeps `lico ...` in the shell talking to this host |
| D3 | `cwd` is checked by the session's own folder check (absolute, exists, readable, not the host's own state or scratch folders) | one rule for where a thing may start; its codes (`folder_missing`, `folder_not_directory`, `folder_protected`, ...) are already the protocol's |
| D4 | At most 8 terminals (`tab_limit`); each keeps 2000 lines of scrollback (the component bounds it at about 10 MB) | the same bound as the browser's tabs; the host's memory guard counts the whole process |
| D5 | The window closing does not end a terminal; `terminal.close` and the host stopping do (`SIGHUP` to the group, `SIGKILL` after one second); a shell that exits stays in the list with its screen and its exit code until it is closed | the milestone's D2; the person reads the last output of a command that failed |
| D6 | `terminal.watch` is the browser's pattern (one blocking call, a condition variable, no timer, a close and a stop wake and release it) **without** its supersede rule: any number of watches of one terminal may wait together | the window needs one call that returns when something changed, and a timer would cost a wake-up per tab per second; with the supersede rule two viewers of one terminal (a second window, or `lico terminal show`) would take the watch from each other for ever, and the milestone's D2 promises that a second client sees the same screen |
| D7 | The pty is non-blocking: one reader thread (`poll`, `read`, feed the emulator, write the replies it asks for back to the shell) and one waiter thread (`wait` for the shell); a write waits at most 2 seconds for room | a shell that does not read must not hold a request thread for ever, nor a reader that cannot be stopped hold the master open |
| D8 | The syscalls (`posix_openpt`, `grantpt`, `unlockpt`, `ptsname_r`, `ioctl`, `poll`, `read`, `write`, `kill`, `prctl`, `setsid`) are called through `extern "C"` in one file (`terminal/pty.rs`), as `procs.rs` does; no `libc` crate | the project pins few dependencies; the unsafe code is one small file with its own tests |
| D9 | The default shell is `$SHELL` (absolute and executable), else `/bin/sh`; `/bin/bash` is not tried between them | `$SHELL` is the person's choice (bash for most); a guess at bash would start a shell the person did not choose on a machine whose `$SHELL` is broken; `/bin/sh` is the one a Linux system has. Found while writing the choice as a pure function (`choose_shell`) |
| D10 | The operations take what they need from the host through `Host { folder, vars }` (the folder check and the environment as values): the socket path builds it from the process, a test gives its own | the tests run real shells in parallel with the other 850 tests of the binary; changing the process environment for a test would race with them |
| D11 | `lico terminal open` with no `--cwd` opens in the folder the command runs in (not the home), and `show TAB --text` prints the screen as plain text | the person who types `lico terminal open` in a folder wants the shell there; `show` as JSON is the window's reading and is unreadable to a person |
| D12 | The shell is started with the hang-up, interrupt, quit, broken pipe, terminate, child and the three job-stop signals at their default action (`signal(sig, SIG_DFL)` between `fork` and `exec`) | **found by the suite run, not by a test**: the run was started under `nohup`, the host inherited an ignored hang-up, and an ignored signal stays ignored through `exec`; the shell could not trap it and its children did not end with the terminal. A host started under `nohup` or a service manager is the usual case, so a terminal must not take that over. Now caught by a real-host test and four mutation checks |
| D13 | A group that ignores the hang-up is killed one second after the close, only when its leader is still the one that was started (start time and group leadership are read before the signal); what an ended leader left behind in another group is not found | a pid read late may be another process; the one-second KILL must not hit it. A known limit, written in the protocol |

## Steps (tests first; each is green before the next)

1. [x] **The plan** (this file) and the protocol table rows in `protocol_v1.md` (0.1.8).
2. [x] **Tests first** (`terminal/` unit tests with a real pty and small shell scripts in a temp folder): open shows the program's first output in the watch; input is echoed by the line discipline and read by the program; the pty's size is the size asked for and a resize reaches the program (`stty size`); a program that exits is `running: false` with its code, and input to it is `terminal_ended`; a signal's exit is 128 + n; close ends the shell **and** a background child of its group (checked in `/proc`) and frees the pty (the file descriptors of the process return to their number); the 9th terminal is `tab_limit`; `cwd` rules; the environment of the child (no `LICO_*`, `TERM`, `COLORTERM`; a pure function tested on its own); the request validators (unknown fields, bounds, `text` against `data`, the tab id); the watch rules (answers at once for `seq` 0, waits otherwise, two watches wait together and both are answered, a close releases them, a stop releases them); the reply for the emulator's own queries is written back to the shell; `text` returns a selection; the colour and run encoding (a style soup of 200 x 60 stays under 3 MB); the socket-only refusal through `dispatch_request` with `via_http`.

[x] **The code**: `terminal/pty.rs` (the syscalls), `terminal/tab.rs` (one terminal: the emulator, the threads, the change number), `terminal/ops.rs` (the table, the validators, the operations, the encoding), `terminal/mod.rs` (`register`); `core.rs` (`OPS`), `admin.rs` (`SOCKET_ONLY_OPS`), the root's `register()`, `terminal_cli.rs` and its two lines in `cli.rs`, `tests/testmap.toml` rows; each file under 800 lines.

## What this phase does not do

The window (the tab, the keys, the fourth icon, the menu entry: P03), a terminal on an ssh host, a login shell or a shell setting, the title of a terminal set by the person, a recording or a replay of the output, the agent's entry into Lico (P04), a terminal over `POST /v1` or MCP (D1), and any change of the emulator `lico-vt` (a fault found in it is fixed in `lico-vt` with its own test, as a separate commit).

## Results (2026-11-18)

- **Code**: `src/host/hostd/src/terminal/` (`pty.rs` 205 lines, the one file that calls the system; `tab.rs` 224; `ops.rs` 230; `encode.rs` 58; `mod.rs` 21; `tests.rs` 775) and `terminal_cli.rs` (151); `core.rs` (the `OPS` line), `admin.rs` (`SOCKET_ONLY_OPS`), `cli.rs` (usage and one branch), `procs.rs` (`start_time` and `signal_group`, which check the start time and the leadership of the group before a signal), `unified.rs` (two lines); `lico-vt` is a dependency of the host and is not changed. No file is over 800 lines.
- **Tests**: 37 Rust unit tests (34 in `terminal/tests.rs`, 3 of the request builder) and 6 Python tests (`tests/test_terminal_cli.py`: the whole command line against a real host and a real shell; the HTTP door refuses all seven operations; a host that stops takes its shells and their children; a shell that ignores the hang-up still does not outlive its host; a shell starts with the default action for the signals its host ignores). `tests/test_control_parity.py` lists the seven operations among the socket-only ones. The whole `cargo test --bin lico` is 903 tests; the changed-files suite is 523 tests in 116 files, all passed (`cargo xtask check`, `verify`, `graph` and clippy on the new files are clean).
- **Mutation checks**: 59, each caught (55 on the first pass, each file restored after each; 4 added for D12). The first pass found five tests that did not yet catch their mutation (a reader that never stops, a close that does not wake a watch, an environment that is not cleared, a missing parent-death signal, a hung watch that waited for the harness's timeout); each got a test or a watchdog before the pass was repeated.
- **Found by the full run, not by a test written for it (D12)**: the first suite run was started under `nohup`; the hang-up was ignored by the host and so by the shells it started, and two tests failed (a `trap` on the hang-up did nothing; a child outlived the host). The fix is in `pty.rs`, with a real-host test that starts the host ignoring the hang-up, the interrupt and the quit.
- **Found on the way**: `/proc/PID/stat` of a process that ends between the open and the read raises `ProcessLookupError`, not `FileNotFoundError` (the test helper caught only the second; it failed one run in four); two of the Rust tests left a `sleep` behind that ignores the hang-up (now killed, or waited for, by the test itself); the first peak of the suite's memory was 2190 MiB against the bound of 2048 MiB (the runs before and after: 2034 and 1908): the margin is thin, and it was thin before this phase (the owner's open item about the suite's margin).
- **Known limit** (D13): a program that left the shell's group, or one that outlived the shell and ignores the hang-up, is not found by the close.
- **Not done, as planned**: the window (P03), a terminal on an ssh host, a recording of the output.
