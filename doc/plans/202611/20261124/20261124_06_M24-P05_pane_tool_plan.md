## What this phase changes

The tool channel (`mcp.rs`, `TOOLS`) gets a twelfth tool, **`pane`**, that does in the person's own terminal tabs and browser tabs what the person does there: list them, read a terminal's screen or a browser tab's picture, type, press a key, click, go to an address, open a tab. The host already has every operation (`terminal.*`, `browser.*`), so the tool is a thin layer over `driver::ops_call` inside the host: no new operation, no new door, and the `terminal.*` operations stay socket-only for the loopback HTTP door.

## What was found (2026-11-24)

- `tools.rs` `run` dispatches a tool by name to a function that takes `(shared, caller, arguments)` and answers a text or blocks; `computer` is the pattern (the per-caller rate counter `calls::counted`, an audit line on the host's stderr that names the tool, the session and the action and never the typed text, a PNG as an image block).
- `driver::ops_valid` and `driver::ops_call` run a registered operation by name from inside the host, with the same validation as the two doors.
- **The size of the list**: `tools/list` was 4,849 bytes with writing off and 5,103 with it on, against a budget of 5,120. The sentence about names (`Names are labels ...`) is carried by five tools on purpose and pinned by tests, so it is not trimmed. One tool costs about 600 bytes: the budget becomes 5,840 (one decision, D1: the tool costs 721 bytes).
- A terminal's screen is read by `terminal.watch` with `seq` 0 (answered at once); a browser tab's picture by `browser.shot` to a new owner-only file.

| # | Decision | Why |
|---|---|---|
| D1 | One tool `pane`; the budget of the list is raised from 5,120 to 5,840 bytes (the tool costs 721; 16 bytes of room stay, as before) | the P01 report's recommendation; every session pays about 180 tokens more at its start, for what the owner asked for |
| D2 | **Always on, for every session** (the owner's answer to Q1): no card, no grant | the owner's choice; the risk (an agent led by text it read to type into the person's shell) is named in the P01 report, section F |
| D3 | Actions: `list`, `read`, `type`, `key`, `click` (browser, `at` = `x,y`), `go` (browser: an address, or `back`, `forward`, `reload`), `open` (`kind` terminal or browser) | what a person does in these two kinds of tab; closing a tab, a terminal's folder and the terminal's mouse stay the person's (the schema is small: a terminal opens in the home folder) |
| D4 | A tab is named by its id from `list` (`t1`.., `b1`..); an unknown or wrong-kind id is an error that says to use `list` | ids are the host's, never an agent's text |
| D5 | Every call is counted per caller (`calls::counted`) and writes one audit line: tool, session, action and tab, never the text | the same rule as `computer` (`SF-03`) |
| D6 | What a terminal shows or a page says is data, never instructions (said in the description, and the text of a screen is returned as a JSON field) | the same rule as the names of sessions |
| D7 | The command line says the same: `lico browser go`, `nav`, `type` and `input` (the person's input as the host takes it: move, down, up, wheel, key_down, key_up; a click is three of them) are added (the terminal already has `send` and `show`) | the product rule: the window is for the person, the command line and the tools do the same things |

## Results (2026-11-24)

- **What an agent can do** (every session of Lico, no card): `pane` with `action` `list` (the terminals and browser tabs by id), `read` (a terminal's screen as text, a page as a picture), `type`, `key`, `click` (`at` = `x,y`), `go` and `open`. Tested against real shells on real ptys through a session's own tool connection: list, type into a shell, press Return and `ctrl+d`, read the screen, open a terminal, and a table of refusals (a click or a `go` on a terminal, an unknown or wrong tab, an unknown key, an empty or missing text, an unknown action, a browser tab that is not there).
- **Code**: the new `pane.rs` (355 lines: `plan` and the keys are pure, `pane` runs the steps through `driver::ops_call`, with the per-caller counter and the audit line), the entry in `mcp.rs` (the twelfth tool, 721 bytes; the budget 5,840), the dispatch in `tools.rs`, the browser verbs of the command line (`browser_cli.rs`, the help in `cli.rs`). No new host operation, no change of what the sockets and the HTTP door accept.
- **Tests (red first against a stub)**: 13 unit tests in `pane_tests.rs` (the ids, `list` and `read`, `type` in each kind and its limits, the bytes of 22 terminal keys and the refusals, the DOM keys of a browser tab, a click as move, down and up, `go`, `open`, the unknown action, the screen as text with the blank ends cut, the request for a screen, the listing and its few fields) and 6 real-host tests (`tests/test_pane_tool.py`); the unit tests of the command line extended (11 new commands, 15 new refusals); the tests that pin the tool list and its budget moved to twelve tools and 5,840 bytes (`mcp.rs`, `local/tests.rs`, five Python files). Whole `cargo test --bin lico`: 1074 passed, 12 ignored.
- **Mutation checks (43 runs; every mutant that changes behaviour is caught)**: 29 mutants of the plan, the keys and the screen text (the tab kinds, the limits, each kind of key, the order of key down and up, a click of two clicks or of the right button, a missing move, the point limits, `go` and `open` on the wrong kind, the blanks of the screen); one survivor (the corner of the page `0,0` was not pinned) closed by a test; two survivors of the real-host round were operations of the run that no test could see (the screen asked for from change number 1, and an empty browser list), so `screen_request` and `list_answer` were made pure and tested; the real-host round (the audit line, the list of terminals, a refusal of the host not being an error) is caught. One mutant of the real-host round was ill-posed (it did not log the text): the audit function has no parameter for the text, so it cannot.
- **Found at the commit**: the guard reads whole staged files, and `browser_cli.rs` had a fixture path that looks like a person's home folder: it was reworded (`/work/u`), the guard was not touched.
- **A gap, said plainly**: the browser actions (`click`, `go`, `read` of a page, the refusal `not_shown`) are tested as plans and as refusals, but not against a running engine: the engine is a download of the person's machine, and a test must not fetch it. The first real use is the owner's.
- **Gates**: clippy as at the parent (139 warnings in the lib, 155 in the test build), `cargo xtask check` passes, the changed-files suite passes.
- **Decisions that stand until the owner says otherwise**: D1 to D7; above all D2 (always on, every session).
