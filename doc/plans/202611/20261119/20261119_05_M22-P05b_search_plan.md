## What this phase changes

1. **A bar that takes words as well as addresses**: what is typed in the bar of a normal tab is an address when it looks like one and a search otherwise (D31).
2. **A search engine the owner can name**: the setting `browser_search` in the host's `browser.json`, a URL with `%s`; without it, the default found by the probe (D32, D33).
3. **The bar says so**: the empty field says `Search or type an address`, the row under an empty page says it, the F1 help says it.

## What was found (2026-11-19)

- `browser.go` and `browser.open` parse what they are given with `lico_browser_view::parse_address` and refuse the rest (`address_invalid` / `bad_request`); a word with no dot (`lico`) is today the address `https://lico`. The window sends what the bar holds, untouched.
- The owner's setting file (`browser.json` of the host's state directory, owner-only, 4096 bytes at most) is read for `engine_dir`, `auto_install`, and (ignored) `stealth`; a file with none of them is an error of the engine setting, so a file that only holds `browser_search` would stop the engine: the new key joins the known keys.
- **The probe (measured, the real Moli engine through the host's fence, a private state folder, three navigations, 2026-11-19)**: the same query `lico 브라우저` (a Latin word and a Korean word: the encoding is part of what is measured), percent-encoded, to each candidate; the page was looked at (a screenshot) and its title and phase recorded.

  | Candidate | Address | Result |
  |---|---|---|
  | Google | `https://www.google.com/search?q=%s` | opened, phase `ready`, title `lico 브라우저 - Google 검색`; the screenshot is a real results page (tabs, ten blue links, Korean query intact) |
  | DuckDuckGo (html) | `https://html.duckduckgo.com/html/?q=%s` | opened, phase `ready`, title `lico 브라우저 at DuckDuckGo`; real results, Korean intact (the search box's button is drawn cut at the right edge: a layout detail of that page) |
  | Bing | `https://www.bing.com/search?q=%s` | opened, phase still `loading` at the sample, title `lico 브라우저 - Search`; real results with a right column, Korean intact |

  All three work with the engine; nothing was blocked and no page asked for a check. One run of three requests is a measurement of this day, not a promise: a site may block an automated browser later (the F1 help already says so), which is why the engine is a setting.

## Decisions (the lead's defaults; the owner may change any)

| # | Decision | Why |
|---|---|---|
| D31 | **What is an address and what is a search** (`lico_browser_view::classify`): an explicit `http://` or `https://` is an address (a bad one stays an error); another explicit scheme (`ftp://`, `file://`), and a scheme with no slashes and no space (`javascript:`, `mailto:`, `data:`), is an error as it is today, never a search; text with a space (or any white space) and no explicit `http(s)://` is a search; text with no space that `parse_address` accepts is an address when its host part has a dot, a port, brackets or is `localhost` (the old explanations for those stay), and a search when it is one dotless word (`lico`); text with no space that cannot be an address (`a<b`) is a search; a user name or password in it, a text too long and an empty text stay errors. Control and hidden characters are removed and white space is collapsed to one space before the words are used | a person types `lico 브라우저` and `lico` and `docs.rs` and `localhost:8080` and means a search, a search, an address and an address; never turning `javascript:` into a request keeps the refusal visible |
| D32 | **The setting** `browser_search` in `browser.json`: a text, an address of the form `https://HOST/PATH?query=%s`: exactly one `%s`, after the host part (the words never become the host), `https` only (the words are not sent in the clear), no white space or control character, short enough that the longest address still fits; the words are percent-encoded (the unreserved `A-Za-z0-9-._~` kept, every other byte of the UTF-8 text as `%XX`, a space as `%20`), and the result must pass `parse_address`. A set value that is not valid is an explicit refusal (`search_setting`, said in the window: the search setting is not a valid address with %s), never a silent fall back to the default. A missing, damaged or group-readable file says nothing: the default | the owner's words; the same reading rules as `auto_install` |
| D33 | **The default engine is Google**, `https://www.google.com/search?q=%s` | the probe: it works with the engine (results page, Korean intact, `ready`); it also worked in the trial of 2026-11-17 (before the change of engine it was the one that did not); it is the owner's own first wish. DuckDuckGo's html page and Bing worked in the same probe and are the two to name in `browser_search` if Google ever blocks the engine |
| D34 | **Who decides**: the component (`classify`, `search_url`, `check_template`, `DEFAULT_SEARCH`: pure, no file), the host (reads the setting, turns the words into the address, in `browser.go` and `browser.open` when the request says `"search": true`), the window (says `search: true`; nothing else). The command line `lico browser open` never says it, so it stays exact; a **local** tab (this machine's services) never searches, whatever the request says: it keeps the old strict parse and its old sentence | one rule in one place; the model needs no file and no clock; a local tab cannot reach a search site |
| D35 | **Words**: the bar's own text is sent as typed (the host classifies it); the longest search is what fits in an address of `MAX_URL` (2048) characters after the encoding, else `address_too_long` | no second limit to explain |
| D36 | `lico-browser-view` **0.9.0** (a new module `search.rs`, re-exported; spec, contract tests in `tests/search.rs`, receipt); the placeholder and the first row say `Search or type an address`; the F1 help gets a line for the search and says the setting's name; `refuse_text` gets `search_setting` and an `address_empty` that says `type an address or words to search` | the bar must say what it takes |
