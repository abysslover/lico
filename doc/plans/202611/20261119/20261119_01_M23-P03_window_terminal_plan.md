## What this phase builds

A **terminal tab** in the window: a tab of its own kind beside the session tabs and the browser tabs (D1), showing the screen of one of the host's terminals (`terminal.*`), taking the person's keys, text, paste and wheel, and following the size of the window. It is made from the Session menu (`New terminal tab`) and from a **fourth icon, Terminal, in the first step of New session**; the window finds the host's terminals again when it starts (the host keeps them, D2). It is built on the browser tab's pattern (`browser_view.rs`: one blocking watch per shown tab, sent after the paint, the answers on the event loop), and every pure part is in a module of its own with tests first.

Not in this phase: the program's mouse reporting (`encode_mouse` is ready; a mouse that vim or tmux asked for is P04 with the other comforts), a terminal on an ssh host, a separate toolbar button (owner's open question), the agent's entry into Lico (P05), the title set by the person.

## What the person sees

- **The tab**: the caption is `>_ ` and the shell's title (else the folder's last name), `x` closes it. The grid fills the main area from under the header to above the bottom row; the cell is the window's own font cell, so the columns are the window's columns. A wide character (Korean) takes two cells and is drawn at its own cell, so the grid never drifts.
- **The header** says `terminal | <title> | <folder> | not fenced: it runs as you`; the bottom row says the keys that are Lico's (`Ctrl+Shift+C copy  Ctrl+Shift+V paste  Shift+PgUp/PgDn history  Ctrl+Shift+W close`), and, when the shell has ended, `the shell ended (exit N): Enter closes this tab`; when scrolled back, `history: N lines up, End or typing returns`.
- **The keys**: everything goes to the shell (Esc, Ctrl+A, Ctrl+C, Alt+letter, the function keys, the arrows with the program's application-cursor mode), except Lico's own (D4). The input method's commit (Korean) goes as text; a paste goes as the program asked (bracketed or not).
- **New session > Terminal**: the fourth icon (never grey, like Local LLM); one more step, the folder (the one-page form's own folder row and recent folders; no account, no worktree, no branch), where Enter starts it; the step says in words that a terminal is a shell that runs as the person and is not in Lico's fence.

## Decisions (the lead's defaults; the owner may change any)

| # | Decision | Why |
|---|---|---|
| D1 | The terminal is a tab of its own kind (`ui.terminal`), not a session and not in Chats; at most one of the browser and the terminal is the shown one (entering one clears the other's `active`) | the milestone's D1; the browser tab is the proven pattern, and a session's whole machinery (transcript, approvals, the input box) means nothing for a shell |
| D2 | The window keeps only the last screen it was told; the host keeps the shell. At start the window asks `terminal.list` and adopts every terminal it finds | the host's D5 (a window that closes does not end a terminal); a terminal of `lico terminal open` shows up as a tab too |
| D3 | One blocking `terminal.watch` for the shown tab, sent after the paint of the last answer (nothing polls); every watch carries a **generation**, an answer of an older generation is dropped. A scroll (wheel, Shift+PgUp) is a watch with `seq` 0 at the new offset (answered at once) and, while the view is scrolled back, no live watch is sent (the view is a still picture; typing or End returns to the live screen) | the host's watch has no cancel, so a stale blocked call may come back later: the generation makes that harmless, and not re-arming while scrolled keeps the number of such calls at one or two |
| D4 | **Terminal first.** The shell gets every key except: Ctrl+Shift+C (copy), Ctrl+Shift+V and Shift+Insert (paste), Ctrl+Shift+W (close the tab), Shift+PgUp/PgDn (history), and any other Ctrl+Shift+letter, which is the window's own namespace (as in the usual terminal emulators) and goes on to the window's handlers; Ctrl+Tab goes on too. Esc does not leave a terminal; the sidebar, the tabs and the menus are for the mouse | a shell and its programs use Esc, Ctrl+A/N/C/R, Alt+letters; a window shortcut that took them would break the shell, and the owner would find out in vim |
| D5 | The colours: default foreground `#E0E0E0` on `#0F131A`; the 16 colours of xterm, the 6x6x6 cube and the 24 greys; true colour as given; bold with an indexed colour 0 to 7 takes the bright one; dim is the colour half way to the background; inverse swaps; underline and strike are lines; blink is not drawn; hidden draws the background only | the standard table; no setting yet (the owner has not asked for themes) |
| D6 | The text is drawn through the window's own shaped-label cache, a segment at a time: a run of narrow characters is one label, a wide character is a label of its own at its own cell; each segment at `x0 + col * cell`. The cache is the one the window already bounds (dropped at 600 labels) | the window has one text path and one font fallback; drawing at the cell makes the grid exact whatever the fallback font's advance is |
| D7 | The grid is `floor(area / cell)` columns and rows, at most the host's 500 x 200, at least 2 x 1; the new size is sent with `terminal.resize` after a paint when it differs from the last one sent (one in flight, the newest wins) and the next watch brings the screen at the new size | the browser tab's rule for its viewport; the host does nothing when the size is the one it has |
| D8 | The one row under the grid is the terminal's status (the keys, the end of the shell, the history); the input box is not shown for a terminal and the editor is not given the keys | the layout needs one prompt row (`n_prompt - 1`); the status row is that row, and a terminal has no draft |
| D9 | Selection is by the mouse over the grid (press, drag, release; a double click is not special yet); the selection is kept as absolute lines and columns (the host's `top` + the row) and painted inverse; Ctrl+Shift+C asks `terminal.text` for it and puts it on the clipboard (the window's own copy, which refuses over 64 KiB); a plain click clears it | `terminal.text` was made for this in P02; absolute lines keep the selection on the same text when the screen scrolls |
| D10 | The fourth icon is `Terminal`, in `PROVIDERS` after Local LLM; its step is the folder (`Field::Folder` and the recent folders), `Next` is `Start` and the title says `step 2 of 2`; the choice is the form's own (`f.terminal`, as `f.local`), so the one-page form's other rows stay as they are. This deviates from the milestone's D4 (a name step): the host's terminal has no name, so a name step would ask for something nothing keeps | no function of the form is lost; nothing is asked that is not used |
| D11 | The menu entry `New terminal tab` opens a terminal at once in the folder of the selected session, else the person's home (no step); the toolbar has no new button | one click for the person who knows what they want; the toolbar question stays open with the owner |
| D12 | A shell that has ended keeps its tab with its last screen; the status row says so and Enter closes the tab (the host's close of an ended terminal is a no-op that removes it) | the host's D5 |

- **Code** (commit `3cf3b6b`; as built, the file names of step 3 above were the first guess): `src/host/hostd/src/gui/terminal/` is one module of the window with `screen.rs` (414 lines: the screen read defensively from a watch reply, the palette, the segments of a run, the grid of an area, the selection, the status row), `keys.rs` (121: the routing of a key to the shell, to Lico or on to the window), `view.rs` (687: the state, the jobs, the watch with its generation, the queue of input, the resize, the paint, the mouse and the wheel, the copy request, the dump `ui.terminal`), `mod.rs` (19) and the three test files (`screen_tests.rs` 356, `keys_tests.rs` 153, `view_tests.rs` 384). The hooks are in `mod.rs` (still exactly 800 lines: only same-line edits), `ui.rs` (1114, the ratchet's own limit), `jobs.rs`, `panel.rs`, `browser_view.rs`, `controls.rs`, `tabs.rs`, `menu.rs`, `picker.rs`, `editor/app.rs`, `telemetry.rs`, `icons.rs`, `newsession.rs` and `newsession_wizard.rs`. No other file is over 800 lines.
- **Tests**: 57 Rust unit tests in `gui::terminal` (25 of the screen, 10 of the keys, 22 of the view), 5 more in the wizard and the menu, and 7 Python tests in `tests/test_terminal_tab.py` against a real host, a real shell and Xvfb (the menu entry; the grid and `stty size` and a window resize; application cursor keys, bracketed paste and Hangul; selection, copy in both directions of the drag, paste and the history with Shift+PgUp and the wheel; two tabs, the cross, Ctrl+Shift+W and the end of a shell; a terminal the host already had and the browser and terminal never both shown; the fourth icon, the folder step and a refused folder; Korean through the input method). `tests/test_icon_toolbar_wizard.py`, `tests/test_login_window.py` and `tests/test_menu_tree.py` were changed for the four icons and the new entry. The whole `cargo test --bin lico` is 953 tests; the changed-files suite is 272 tests in 78 files, all passed (peak 2010.6 MiB against the bound of 2048 MiB); `cargo xtask check`, `verify` and `graph` are clean; clippy has nothing on `gui/terminal/` (the six errors it reports are in `editor/app.rs` and `llm/net.rs`, on lines this phase did not write).
- **Mutation checks**: 53, 52 caught and 1 equivalent (W04: the window sends an empty folder as an empty string, and `terminal_open` drops a folder that does not start with `/` itself, so the host sees the same request). 46 are checked by the Rust tests, 7 by the real-host window tests (`kind "py"`: the menu entry and the six calls to the host). The first pass caught 35 and left 17: the cause of most was that a winit `KeyEvent` cannot be made in a test, so the routing of a key was only reachable through the window; the key function was split (`terminal_hotkey` reads the event, `terminal_key` takes what it needs) and the survivors got Rust tests; the 16 survivors that could be run again and the one mutation whose text no longer compiled (V16) were run again after the split, and each was caught. One of them (the order of a selection's ends in the copy request) could not be seen through the window at all, because the host orders the two ends itself ("either order"): the request was made a function of its own (`text_request`) with a test. The 35 that were caught on the first pass were not run again after the split of the key function (the code they mutate is the same); P06 was, because its line moved.
- **Found on the way**: the status row first wrapped to two lines at the window's width (now 85 characters, and a test that it stays under 100); Ctrl+Tab steps the *sessions* only, so the hint now says `Ctrl+Tab next session` and a test clicks the terminal tabs; Ctrl+N goes to the shell while a terminal is shown, so the window test starts New session with the toolbar button; the check that tells the window whether there is a place for typed text (`has_prompt_target`) says yes for a terminal, so that the window's commit and paste reach it; a refused folder says `that folder cannot be used for a terminal (folder_missing)` in the header.
- **Known limits**: the program's mouse reporting is not sent (a later phase, with the other comforts); a double click does not select a word; the terminal has no setting for the font or the colours; the selection is by cells, and the host keeps at most eight terminals (a ninth is refused and the window says why).
- **Not done, as planned**: the mouse of vim and tmux, a terminal on an ssh host, a toolbar button, the agent's entry into Lico (the next phase of M23), the title set by the person.
