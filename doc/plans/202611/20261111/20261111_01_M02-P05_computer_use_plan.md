## Goal

An agent in a Claude Code session can operate a private per-session virtual X11 display (`Xvfb`, `1280x800x24` by default) without disturbing the person's desktop: start programs on it (`DISPLAY=$(lico display) command` or `lico display run -- command`), look at the screen, click (left, right, middle, double), move, drag, type text, press key combinations, scroll and wait through XTEST, receiving a shrunk PNG screenshot (`<= 1568 px` long side) after each action with coordinates expressed in that shrunk image. The person's real screen is off by default (SF-06) and is touched only after an explicit per-session approval in `lico gui` that lasts at most 15 minutes, shows a conspicuous top warning bar with countdown and `[ Stop now ]`, stops at once on `Ctrl+Alt+Esc` (or menu / CLI), logs each action without screen contents or typed text (SF-03), and vanishes on host restart (CU-06). Human administrators can also start and stop a session's virtual display and stop real-screen control directly from the `Session` menu in `lico gui`.

**Order of the steps:**
- **S01 (focus and XTEST measurement, CU-08, CU-02):** enable `x11rb` `features = ["xtest"]` (no new crate, offline lock unchanged) and measure on a private `1280x800x24` `Xvfb` without a window manager how real X11 clients (`xmessage`, `xcalc`, browser window) receive keyboard focus, comparing raw `PointerRoot` against explicit `SetInputFocus` to the target mapped window inside the helper, and recording `Xvfb` resident memory (`VmRSS` / `RssAnon`).
- **S02 (per-session virtual display and CLI, CU-01, CU-04, MB-03):** module `vdisplay` managing one `Xvfb` (`1280x800x24`, `-nolisten tcp`, `-displayfd`) per asking session; stopped after 10 idle minutes (`600 s`), on `session.close`, on `session.purge` and on `host.stop`; counted in that session's memory figure (`memory::annotate`); exposed over socket ops `display.ensure`, `display.status`, `display.stop` and CLI `lico display`, `lico display run`, `lico display status`, `lico display stop`, with `LICO_SESSION` and `LICO_SOCKET` passed to Claude sessions so `DISPLAY=$(lico display) cmd` works directly.
- **S03 (XTEST action helper and coordinate scale, CU-02, CU-03, XF-07):** module `computer` (`job.rs`, `xact.rs`) registered as hidden `xjob` `"computer"`, executing `look`, `click` (`left`, `right`, `middle`, `double`), `move`, `drag`, `type`, `key`, `scroll` and `wait` on a named `DISPLAY`, converting shrunk-image coordinates `(x, y)` to screen coordinates via the documented capture scale, giving X11 input focus to the target mapped child window when no WM is running, and returning the post-action shrunk PNG via `capture::run` with zero standing host X11 connection.
- **S04 (MCP `computer` tool, real-screen gate, audit log, and `lico gui` controls, CU-05, CU-06, SF-01, SF-03, SF-05, SF-06):** `computer` on the Claude MCP tool channel (`LIST_BUDGET = 5120`), defaulting to `target = "virtual"` (starts the session's virtual display on demand, no prompt) and gating `target = "real"` behind a memory-only 15-minute (`900 s`) per-session grant approved in `lico gui` (`keep` refused); host audit line per action without screen pixels or typed secrets; socket op `real_screen.stop` and CLI `lico real-screen stop`; `gui/realbar.rs` drawing the crimson warning bar (`!! REAL SCREEN: '<name>' is controlling this screen   MM:SS left   [ Stop now ]`), `Ctrl+Alt+Esc` shortcut anywhere in `lico gui`, and `Session` menu items for virtual display start/stop and real-screen stop.
- **S05 (real-program virtual-display check, measurements, and report, CU-07, MB-04, TST-01, TST-10):** opt-in `claude` (`haiku`) check on the virtual display opening a real X11 browser/window and reading its title, warm `--cold` full-suite verification (`<= 180 s`), `idle_memory` at scales 1 and 2 (`< 50 MiB`), local inspection bundle, and `M02-P05` report `0.1.0`.

## What exists already (read on 2026-11-11)

- `capture` (`src/host/hostd/src/capture/mod.rs`) captures `--screen`, `--window` or `--region` in 256 KiB bands and writes both full and shrunk (`<= 1568 px`, `scale` reported) PNGs with no external crate.
- `xjob.rs` and `helper/mod.rs` run short-lived X11 jobs in their own process group with pipe polling, timeout `SIGKILL`, group reap and zero standing X11 state in `lico-host` (*measured* in P04-S08: `+0` threads, `+0` fds, `+0` children after 20 jobs).
- `x11rb = "=0.13.2"` is already pinned in `Cargo.toml` and cached offline together with `x11rb-protocol 0.13.2`, which includes `protocol::xtest`.
- `pending.rs`, `calls.rs`, `screentools/mod.rs`, `tools.rs` and `mcp.rs` already serve 8 Claude-only MCP tools (`4,078` bytes of the `4,096`-byte `LIST_BUDGET`) and return `Answer::Blocks` carrying JSON metadata plus `image/png` base64 blocks; `lines.rs` and `claude.rs` already stream-cut large `tool_result` image lines safely (`XF-08`).
- Line-count ratchets (`tests/size_allowlist.toml`): `core.rs` is at `1,087 / 1,087` lines and `gui/ui.rs` is at `1,161 / 1,185` lines; neither may exceed its allowlist ceiling, and every new `.rs` or `.py` file must stay `<= 800` lines (`TST-07`).

## Coordinate scale rule (CU-03)

For a full-screen capture of `(W, H)` pixels, `capture::shrink::agent_size(W, H, 1568)` yields `(AW, AH)` where:
- If `max(W, H) <= 1568` (including the default `1280x800` virtual display), `AW = W`, `AH = H` and `scale = 1.0`: shrunk-image coordinates equal screen coordinates (`screen_x = x`, `screen_y = y`).
- If `max(W, H) > 1568` (for example `1920x1080`, where `AW = 1568`, `AH = 882`, `scale = 1568 / 1920 = 0.816666...`), an agent point `(x, y)` in `[0, AW - 1] x [0, AH - 1]` maps to screen pixel:
  `screen_x = round((x + 0.5) * W / AW - 0.5)` clamped to `[0, W - 1]`, and `screen_y = round((y + 0.5) * H / AH - 0.5)` clamped to `[0, H - 1]` (pixel-centre mapping, exact inverse of the box shrinker in `capture/shrink.rs`).
The JSON text block returned alongside every `computer` screenshot states `width`, `height`, `agent_width`, `agent_height`, `scale`, and (for pointer actions) the resolved `screen_x` and `screen_y`.

## Deviations and refinements

- **D1 (CU-08, focus without an external window manager):** no standalone window manager (`openbox`, `twm`, `fluxbox`, `jwm`) is installed on the reference machine, and requiring one would add both an external runtime dependency and per-session resident memory. S01 measures raw `Xvfb` focus behaviour first and verifies whether setting X11 input focus (`SetInputFocus` to the mapped top-level child window under the pointer, or the topmost mapped child of root when typing without a pointer move) inside `xjob computer` delivers key and text events reliably to real X11 programs (`xcalc`, `xmessage`, browser) with `0 MiB` standing WM RSS. If a client class still fails, S01 records it before S03 freezes.
- **D2 (`mcp.rs` `LIST_BUDGET` `4,096` -> `5,120` bytes):** adding the 9th tool `computer` with concise argument descriptions crosses the `4,096`-byte cap (`4,078` bytes used in P04); as pre-noted in M02-P04 Deviation D13(f), `LIST_BUDGET` moves to `5,120` bytes (`~1,280` tokens per session).
- **D3 (CU-05, CU-06, real-screen two-step start and 15-minute window):** consistent with AC-03 and P04's `capture`, the first `computer` call with `target = "real"` when no live grant exists returns `{"status": "pending", "approval_id": ...}` immediately without blocking HTTP; when the person clicks `Allow` (`Y`), the host records a memory-only 15-minute (`900 s`) grant for that session (`keep: true` is refused so real-screen access can never become indefinite) and wakes the session with a notice. Subsequent `target = "real"` calls within those 15 minutes execute immediately, log an audit line (`tool=computer target=real session=<id> action=<act>`), and stop the instant the timer expires, `real_screen.stop` (`Ctrl+Alt+Esc` / `[ Stop now ]`) runs, the session closes/purges, or the host restarts.
- **D4 (`TST-01` suite-time budget):** warm `--cold` suite time at P04 close is `178.0 s` against the `180.0 s` hard ceiling. All P05 unit logic (coordinate conversion, key combo parsing, grant expiry, reaper, bar layout) is tested in fast Rust unit tests, and the end-to-end Python test file (`tests/test_computer_use.py`) reuses a single fixture scope so the cold suite stays under `180.0 s`.
