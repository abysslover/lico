## Objective

Three new components, no change to the program (no dependency of `lico` on them yet; `Cargo.lock` changes only by adding the three members): a WebSocket client and server framing (`lico-ws`), a scripted fake CDP server for tests (`lico-cdp-fake`), and a CDP client (`lico-cdp`). The engine is not involved: every test talks to the fake on an ephemeral loopback port. The message shapes are **KNOWN FROM DOCUMENTATION** (RFC 6455; the Chrome DevTools Protocol's public reference) or **PROPOSED**; the ones the engine may do differently (what `Page.startScreencast` sends, whether `Input.insertText` exists) are marked and are re-fitted after the first measurement of P03. Rules: component rules 1.0.1 (version, `SPEC.md`, contract tests, receipt, 256 MiB and 30 s), downward-only dependencies, tests first, no secret in any `Debug` output, no new Python.

## Specification drafts (the lead reads them with the question file; no owner stop)

### `lico-ws 0.1.0` (std only; depends on nothing)
Purpose: WebSocket (RFC 6455) between two ends on this machine: the client role for the CDP client, the server role for the fake. Loopback addresses only, no TLS, no proxy, no name lookup, no extensions, no subprotocols.

| Name | Meaning |
|---|---|
| `Limits { connect, handshake, idle, max_message, max_head }` with `Default` (3 s, 3 s, 30 s, 8 MiB, 16 KiB) | the deadlines and the caps |
| `Request { addr, path, headers }` | the target of `connect` (`Host` is built from `addr`; no `Origin` is ever sent) |
| `connect(&Request, &Limits) -> Result<Conn, Error>` | connect, upgrade, check `Sec-WebSocket-Accept` |
| `accept(TcpStream, &Limits) -> Result<(Conn, Head), Error>` | the server role: read the upgrade request, answer 101 (`Head { path, headers }`: names lower case) or refuse with 400 |
| `Conn::send_text(&str)`, `send_binary(&[u8])`, `recv() -> Result<Message, Error>`, `set_read_timeout(Option<Duration>)`, `close(code)`, `canceller() -> Canceller` | `Canceller::cancel()` (from another thread) ends a blocking `recv` with `Error::Cancelled` |
| `Message { Text(String), Binary(Vec<u8>), Close { code, reason } }` | pings are answered inside `recv`; a pong is dropped; fragments are joined |
| `Error { NotLoopback, Connect, Refused(status), Handshake(&'static str), Timeout, Cancelled, Protocol(&'static str), TooBig, Closed, Io(kind) }` | `Debug` never shows a header value |
| `accept_key(key) -> String`, `encode_frame(opcode, payload, mask: Option<[u8;4]>) -> Vec<u8>`, `Decoder::new(role, max_message)`, `feed(&[u8]) -> Vec<Result<Frame, Error>>` | the pure parts (SHA-1, base64, framing): tested with no socket, with the RFC's own examples |

Invariants: client frames are masked and server frames must not be (else `Protocol`); reserved bits, unknown opcodes, a control frame over 125 bytes or fragmented, a continuation without a start, invalid UTF-8 in text: `Protocol`; a message over `max_message` is `TooBig` before it is buffered whole; the server may not answer with `Sec-WebSocket-Extensions` or a subprotocol (`Handshake`); the `Authorization` value, if the caller sends one in `headers`, appears in no `Debug`, error or log; `Drop` closes the socket; no thread is started.

### `lico-cdp-fake 0.1.0` (depends on `lico-ws`, `serde_json`)
Purpose: a scripted fake of a CDP endpoint on `127.0.0.1:0` for tests: plain HTTP GET rules (discovery), the WebSocket upgrade (optionally requiring `Authorization: Bearer TOKEN`), scripted replies to methods and scripted events, and recorded calls.

| Name | Meaning |
|---|---|
| `Fake::start(Script) -> io::Result<Fake>`, `addr()`, `calls() -> Vec<Call>`, `heads() -> Vec<Head>`, `stop(self)` | `Call { method, params, session_id }`; `Head` as in `lico-ws`; `stop` (and drop) returns within about 2 s |
| `Script::new().token(&str)`, `.http(path, status, body)`, `.on(method, Answer)`, `.times(n, method, Answer)` | rules in order; no rule for a method answers with the CDP error `-32601` |
| `Answer { Result(Value), Error { code, message }, Silent, Close }` with `.event(method, params)` (sent after the reply), `.after(ms)` | a reply, a CDP error, no reply, or the end of the connection |
| `screencast_frame(session, data_b64, w, h, n) -> Value` | the params of a `Page.screencastFrame` event in the Chrome shape (**PROPOSED**: re-fitted to the engine after the measurement) |

Invariants: loopback only; bounded (head 16 KiB, message 8 MiB, a connection idle 5 s ends); a wrong or missing token is a 401 before the upgrade; every call that arrives is recorded; `Silent` never answers and `Close` ends the connection without a close frame.

### `lico-cdp 0.1.0` (depends on `lico-ws`, `serde_json`)
Purpose: a synchronous CDP client over one WebSocket: ids, replies matched to calls, events queued; no thread, no async.

| Name | Meaning |
|---|---|
| `Client::connect(addr, path, token: Option<&str>, &Limits) -> Result<Client, Error>` | the token goes into one `Authorization: Bearer` header and nowhere else |
| `call(&mut self, method, params: Value, session: Option<&str>, timeout) -> Result<Value, Error>` | the `result`; events that arrive meanwhile are queued |
| `next_event(&mut self, timeout) -> Result<Option<Event>, Error>`, `dropped() -> u64`, `canceller()` | `Event { method, params, session_id }`; the queue holds at most 64, the oldest is dropped and counted |
| `Error { Remote { code, message }, Timeout, Cancelled, Closed, TooBig, Protocol(&'static str), Ws(lico_ws::Error) }` | a CDP error reply is `Remote` |
| `cmd::navigate(url)`, `set_viewport(w, h, scale)`, `start_screencast(format, quality, max_w, max_h, every_nth)`, `screencast_ack(session_id)`, `capture_screenshot(format)`, `mouse(kind, x, y, button, clicks, delta)`, `key(kind, key, code, text)`, `insert_text(text)`, `create_target(url)`, `attach(target_id)` | pure builders of the params (**KNOWN FROM DOCUMENTATION**: Chrome's names; the engine may lack some: the measurement says which) |

Invariants: ids start at 1 and rise; a reply with an id nobody waits for is ignored and counted; a message that is not a JSON object is `Protocol` and ends the connection; a message over the cap is `TooBig`; the token appears in no `Debug` or error; no reply is ever handed to the wrong call.

## Tests first, and what cannot be red first

For each component the contract tests (`tests/contract.rs` names every public item) and white-box tests are written before the code and seen red (a compile error counts); `lico-ws` starts with the RFC 6455 examples (the accept key `s3pPLMBiTxaQ9kYGzzhZRbK+xOo=` for `dGhlIHNhbXBsZSBub25jZQ==`, the masked `Hello` frame, fragmentation, a 16-bit and a 64-bit length), then the invariants above one by one, then client against server over loopback. `lico-cdp` is tested against `lico-cdp-fake` (a dev-dependency: an input of the tests, not a dependency). The thread of the fake's accept loop cannot be red first on its own; it is proved by the client tests that need it. Mutation checks as in M16 (the invariants), with the figures reported.
