## Why (the lead's reasoning, mail 147 section 2, NOT measured)

The fence of P03 allowed TCP to one fixture port. A tab that opens real sites needs the engine to reach the internet, and Landlock ABI 4 filters TCP by PORT, not address: opening 80 and 443 would let a compromised engine reach any loopback or LAN service on those ports, the engine's own private-network block is a check inside the process the fence contains, and DNS (UDP) is not covered. So Lico runs a small **fetch guard** of its own inside the host, on loopback, only while an engine runs; the engine gets `--proxy` pointing at it; the fence then allows TCP to the guard's port and the CDP port only; the guard resolves names itself, refuses addresses that are not public (unless a tab was opted into `localhost`), connects to the address it checked, tunnels `CONNECT` bytes without looking inside (TLS stays end to end) and has caps. The spec sentence becomes: "Lico passes no stealth switch and sets no stealth variable; it passes `--proxy` only to its own loopback fetch guard."

## Specification draft: `lico-proxy 0.1.0` (std only; threads only while it runs)

`Proxy::start(Config, Arc<dyn Resolver>, Arc<dyn Connector>) -> io::Result<Proxy>` binds `127.0.0.1:0` (never another address) and starts one acceptor thread and one thread per connection (a small stack); `addr()`, `stats()`, `stop(self)` (every connection is shut down; it returns within about 2 s). **No thread exists before `start` or after `stop`.** `Resolver::resolve(host, port, timeout)` (the std implementation behind a deadline helper; IP literals never reach it) and `Connector::connect(ip, port, timeout)` (the std implementation; a fake in every test that maps a "public" address to a local origin, so that even the public-address rules are tested with no real network). `Config { token, max_connections, limits, policy, observe }`; `Policy { allow_loopback }` (the per-tab `localhost` opt-in; private, link-local and every other non-public range are never allowed); `observe` is a callback that receives `Event { kind, host, port, authenticated }` (never a path or a query).

**Safe shape of plain `http://` through a proxy** (where request smuggling lives): ONE destination per connection, fixed by the first request line or the `CONNECT` line; the request is rewritten to origin form with the `Host` of the destination, hop-by-hop headers dropped (`Connection`, `Proxy-Connection`, `Keep-Alive`, `TE`, `Trailer`, `Upgrade`, `Proxy-Authorization`, `Expect`), `Connection: close` forced both ways; a request body only with `Content-Length` (at most `MAX_BODY`); **any `Transfer-Encoding` in a request, a `Transfer-Encoding` together with `Content-Length`, two different `Content-Length`s, a folded header, an absolute-form line with a user name or password, an `https://` absolute form, an origin-form line, a header block over `MAX_HEAD`, more than `MAX_HEADERS` headers, and bytes after the first request (a pipelined second request, whatever host it names) are refused and the connection is closed without anything reaching the origin.** The response head is rewritten to `Connection: close` (no keep-alive survives) and its body is relayed raw until the origin closes, within the byte and time caps. `CONNECT` goes to `host:port`: public destinations only on `PUBLIC_PORTS` (80, 443, 8080, 8443), a loopback destination (opt-in) on any port; the tunnel is raw bytes in both directions.

**Address policy as data** (one test per row of the table in the SPEC): IPv4 `0/8` unspecified, `10/8` private, `100.64/10` shared, `127/8` loopback, `169.254/16` link-local, `172.16/12` private, `192.0.0/24` reserved, `192.0.2/24` documentation, `192.88.99/24` reserved, `192.168/16` private, `198.18/15` benchmark, `198.51.100/24` and `203.0.113/24` documentation, `224/4` multicast, `240/4` reserved, `255.255.255.255` broadcast; IPv6 `::` unspecified, `::1` loopback, IPv4-mapped `::ffff:0:0/96`, NAT64 `64:ff9b::/96` and 6to4 `2002::/16` classified by the IPv4 address inside, IPv4-compatible `::/96` reserved, `fc00::/7` and `fec0::/10` private, `fe80::/10` link-local, `ff00::/8` multicast, `2001::/32` (Teredo), `2001:db8::/32`, `100::/64`, `64:ff9b:1::/48` reserved or documentation, everything outside `2000::/3` reserved; only `Public` is allowed, and `Loopback` with the opt-in. **Resolve once:** a name is resolved once per connection, **every** answer is classified and the name is refused if ANY answer is not allowed (a name that resolves to a mix), and the connect goes to the address that was checked (never a second lookup: a rebinding answer is never seen). **Numeric tricks:** a host whose labels are all digits or `0x` hex but that is not a strict dotted quad (`127.1`, `2130706433`, `0x7f.0.0.1`, `0177.0.0.1`), a non-ASCII host and a host over 253 bytes are refused before any lookup (the system lookup would read them as addresses).

**Limits (named constants with reasons in the SPEC):** `DEFAULT_MAX_CONNECTIONS` = **16** (a page opens at most six connections to a host and a few hosts: 16 is room, and each costs one or two threads of 256 KiB of stack, about 3 MB of the host's memory at the very most, only while an engine runs; the next one gets a 503), `MAX_HEAD` 16 KiB, `MAX_HEADERS` 100, `MAX_BODY` 16 MiB, `DEFAULT_CONNECT` 10 s, `DEFAULT_RESOLVE` 5 s, `DEFAULT_IDLE` 60 s, `DEFAULT_TOTAL` 300 s, `DEFAULT_MAX_BYTES` 256 MiB per connection. **The token:** if the engine takes proxy credentials, `Proxy-Authorization: Basic` with the user `lico` and a per-start random token is required (a 407 otherwise, compared in constant time, in no `Debug`); the measurement says whether the engine sends it.

**Memory and the idle host (counts against Lico):** the proxy is started by the host adapter (P06) only with an engine and stopped with the last tab, so a host with no tab has no listener and no thread; how it will be shown when the adapter exists: the host's idle RSS (8.19 MiB at `0.4.0`) and its thread count are measured with no tab and compared; and a test of this component shows that after `stop` no connection and no listener remain.

## Tests first, and what cannot be red first

Pure parts first (the address table, the host rules, the request parser and rewriter, the response head rewriter), then the sockets against a fake origin, a fake resolver and a fake connector on loopback. Every refusal in the "safe shape" list has a test that shows the origin saw nothing; every row of the table has a test; the resolve-once rule is shown with a resolver that gives a private answer on its second call. The standard-library resolver and connector are thin and cannot be tested without a real lookup or a real connection, which no test may make: they are covered by reading and by the measurement (P05's probe uses the real connector to a loopback fixture; the real resolver is never run). Mutation checks as in M16 and M17-P02 to P04.
