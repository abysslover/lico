## Objective

The host side of a browser tab, with no window yet: the host starts the engine only when a tab asks, runs it behind `lico-sandbox` and `lico-proxy` with the decided profile, drives it with `lico-cdp`, keeps one `lico-browser-view` model per tab, ends the engine with the last tab, and offers `browser.open`, `browser.list`, `browser.close` and `browser.shot` with CLI and HTTP parity. The window (P07) and the input (P08) come later; the adapter is built so that they only add operations.

## What the measurements changed in the plan (the lead should know before reading on)

1. **The engine's version answer names Chrome, not the engine.** MEASURED (P03): the discovery answer `/json/version` names `Chrome/145.0.0.0`; the text of `Browser.getVersion` itself was called but not recorded in the notes, and the probe of this phase records it. Mail 149 asks that the engine version in the honest user-agent come from the engine's own `Browser.getVersion`; if that text names Chrome it would put a false Chrome version in it. **My proposal:** the engine part of the user-agent is the PINNED RELEASE constant of the product (`Obscura/0.2.6`), true because the binary was hash-checked against that release; for an engine run under the explicit unpinned setting it is `Obscura/unpinned`. The text: `Mozilla/5.0 (X11; Linux x86_64) Lico/<lico version> Obscura/<release>`, claiming no Chrome version. The banner of the engine ("Headless Browser v0.2.6") is not parsed.
2. **The window cannot hold the model, the host does.** The model of a tab lives in the host (it carries the effects to the engine and receives the frames); the window, a separate process, will read state and the newest frame through operations in P07. In P06 a tab opened from the command line is treated as shown at a default viewport of 1024x768 so that its screencast runs and `browser.shot` has a frame.
3. **A `lico-sandbox` change is needed to close the check-then-run gap** (section 4).

## 1. The fence profile (decided in mail 149 section 1; recorded here)

`read_exec`: the engine's directory, `/usr`, `/lib`, `/lib64`; `read`: `/etc/ld.so.cache`, `/dev/urandom`, the Korean font directory; `read_write`: one scratch directory and `/dev/null`; TCP connect: the guard's port ONLY; bind: the CDP port; environment: the CDP token, an empty `HOME` and `OBSCURA_PROXY` with the per-start credentials; no private-network variable, no 80, 443, DNS or resolver files; the 80 and 443 fallback is not built. `--port 0` is not used: Lico picks a free port for each of the CDP and the guard, allows exactly those, and retries a bind error up to **3 times** (each with a log line "the engine could not bind its port, trying again").

## 2. Where it plugs in, and which hubs gain an edge

The adapter is `src/host/hostd/src/browser/` (one module with submodules), registered once in `unified.rs`. **No hub names it.** The hubs reach it through the driver port (`driver.rs`, M16-P06), which gains two small, std-only-plus-`serde_json` parts (the port names no module of the program):
- `driver::register_ops(Arc<dyn Ops>)` and `driver::ops_for(op)`: `trait Ops { names() -> &[&str]; valid(op, request) -> bool; call(shared: &Opaque, op, request) -> Result<Map, &'static str> }`;
- `driver::on_stop(fn())` and `driver::stop_all()`: hooks that the host runs when it stops (so that the engine and the guard end with the host).

Edits of the hubs (each small, each tested through a dummy `Ops`, so the hubs are proved without the adapter): `core.rs` (the four operation names are added to `OPS`, so `capabilities` lists them; `host_stop` runs `driver::stop_all()`); `ipc.rs` (`valid_request` and `dispatch_request` hand an op that starts with `browser.` to `driver::ops_for`); `cli.rs` (the subcommand `lico browser ...` builds the request like `lico llm discover` does; it goes in a small helper if `cli.rs` would pass the size limit of 800 lines: it is at 751); `http.rs` (the same request map reaches `valid_request` and `dispatch_request`; a test shows both doors answer the same, as for `session.create`). **New edges, all to layer 0 and none into the adapter:** `ipc`, `core`, `cli` and `http` to `driver` (the first two exist), `unified` to `browser`; the adapter imports `core` (for the host's state directory and log, as `local` does: `core` fan-in +1), `driver`, `lico_sandbox`, `lico_proxy`, `lico_cdp`, `lico_browser_view`, `lico_frame`, `lico_png`. The strongly connected component stays at **48**: measured by `cargo xtask graph` before (`178` modules) and after, and a test of the tools (as for `local`) reads it: `browser` is not in the cycle and only `unified` names it. Size ratchet: no file passes its limit (`core.rs` is at 899 of 941, `ipc.rs` 506, `http.rs` 706); counted at the end.

## 3. The supervisor (threads exist only while an engine runs)

- **No process, no thread, no socket without a tab.** `browser.open` starts what is needed: the guard (a listener thread and a thread per connection, `lico-proxy`), the engine under `lico-sandbox` (a child of the host in its own session, `PR_SET_PDEATHSIG` as in P03), and **one worker thread per engine** that owns the `lico-cdp` client (it is synchronous, one owner): it takes commands from a queue, reads events with a 100 ms timeout (so a command waits at most 100 ms; while an engine runs this thread wakes ten times a second: said plainly and measured, not hidden), acknowledges each frame at once, feeds the models and calls `tick`. When the last tab closes, or the host stops, the worker ends the engine (SIGKILL of its process group after a 1 s grace for `Browser.close`), stops the guard, joins its threads and removes the scratch directory.
- **Two engines at most (choice 2 of mail 149):** one for ordinary tabs (the guard's policy: public addresses only) and one for tabs opened with the `localhost` opt-in (the guard's policy adds loopback); each engine has its own guard. The resolver of the opted-in guard answers the name `localhost` itself (`127.0.0.1`) and never asks the system for it.
- **A tab = one CDP target and one flattened session; one `Tab` model each.** Effects of the model become calls (`Navigate` to `Page.navigate`, `SetViewport` to `Emulation.setDeviceMetricsOverride`, `StartScreencast` to `Page.startScreencast` with `png`, `Ack` to `Page.screencastFrameAck`, `CaptureScreenshot` to `Page.captureScreenshot`, `Reload`); the engine's events become `EngineEvent`s (`Page.screencastFrame`, `Page.frameNavigated` of the top frame, `Page.frameStartedLoading`, `Page.loadEventFired`, the title from `Target.targetInfoChanged`, `Target.targetCrashed` and a closed socket). The mappings are pure functions with tests; the base64 of a frame is decoded by a small function of the adapter (tested).
- **Honest user-agent** at the start of each page session: `Emulation.setUserAgentOverride` with the text of the first section (MEASURED in P03: it changes the user-agent and not the `platform` or the `vendor`; the tab's help, P07, says so).
- **Fonts:** the first directory of the fixed list `/usr/share/fonts/truetype/nanum`, `/usr/share/fonts/truetype/noto`, `/usr/share/fonts/opentype/noto`, `/usr/share/fonts/truetype/unfonts-core`, `/usr/share/fonts/truetype/baekmuk` that exists and holds a file whose name contains `Nanum`, `Noto` with `CJK`, `Baekmuk` or `Un` (a Korean font by name); none: the tabs get `NoFontFound` and show the message; no `HOME` fonts and no recursion.
- **What the guard saw reaches the person:** the guard's `Event` with `Refused(status)` is turned into a notice of the tab(s) that are loading (`403`: "this address is on this computer or a private network, which this tab does not open", `502`: "the address could not be found or reached", `504`: "the address took too long"); the engine itself shows a blank page (MEASURED). Because the guard does not know the tab, the notice goes to every tab that is loading whose current host is the event's host, else to every tab that is loading (a limitation, said in the SPEC). **This needs a small versioned change of `lico-browser-view` (0.2.0: `EngineEvent::FetchRefused { status, host }`, `EngineEvent::UnpinnedEngine`, `Tab::notice()`; tests first)** and is made in its own commit before the adapter uses it. A literal numeric loopback address typed by the person is refused by the engine before the guard: the notice is "the engine refuses numeric local addresses; type localhost" (the adapter recognises the engine's own refusal text only through the tab having no guard event and `Page.navigate` returning the engine's `Access to private/internal IP address` error: that text is matched once, in one place, and a change of the engine's wording only loses the nicer message).

## 4. The engine: where it lives, the hash, and the gap

- **Place:** `$XDG_DATA_HOME/lico/browser/v0.2.6/obscura` (default `~/.local/share/lico/browser/v0.2.6/`), with `obscura-worker` next to it. The owner puts it there by extracting the release archive. **Accepted only if** the directory and the file are owned by the user and not group or world writable, the file is a regular file opened without following a symlink (`O_NOFOLLOW`) and its name is exactly `obscura`; else the tab shows why. Parents are not checked: a process of another user cannot change a file in a directory that only the owner can write, and a process of the same user already has the owner's rights.
- **Pinned constants of the product:** release `v0.2.6`; the archive URL `https://github.com/h4ckf0r0day/obscura/releases/download/v0.2.6/obscura-x86_64-linux.tar.gz`; the archive's SHA-256 `eed986e478c5ec5439f531f2d7fb6b0e36a356f1df7a6c44a8e8fd4f2486bd76` (so that the owner can check the download); the SHA-256 of `obscura` `c1400eec0b1572ea9b583b1544feafb0b25cea4e155b353dbba9c144d94ae6e3` (what Lico checks) and of `obscura-worker` `d1025e540736b494d5c3fefe5abc09f3a774c65d9be891d818b0eb374d34dd72`.
- **The check-then-run gap, closed for the engine:** open the file once, check its owner and mode with `fstat` on the open descriptor, hash the OPEN descriptor, and run THAT file: `lico-sandbox` gets a small versioned change (`0.2.0`: `Confinement.run_fd`, tests first, among them a test that the confined child runs the file that was opened and hashed even when the path is replaced by another file after the hash) so that the program is started as `/proc/self/fd/N` of the descriptor that was hashed (the kernel resolves the descriptor at `execve`; the Landlock rule of the engine's directory still grants the execute right to that very file). **What remains, said exactly:** `obscura-worker` is hashed with the engine but not run by `serve` (P03 and P05: one `execve` only); if a later engine version starts it, it would be run by path, and a same-user process could swap it between the check and that start (the same-user process already has the owner's rights; another user cannot write the directory). The adapter refuses an engine whose directory is writable by others, so a different user cannot be the swapper.
- **No bypass.** No environment variable and no flag skips the hash. The only way to run another engine is an explicit setting `browser_engine_unpinned` (a directory path) in the host's owner-only settings file (set with `lico settings`), shown in every tab as "running an engine that is not the pinned release" (`UnpinnedEngine`); the system tests set it in their private home.
- **The absent engine:** the `Absent` phase of the tab with the release URL as text, the archive's SHA-256, the expected SHA-256 of the program, and the directory to put it in. Lico never downloads.

## 5. Operations, parity, limits

`browser.open {url, localhost?}` (the address is parsed by `parse_address`, `http` and `https` only; replies `tab` (`b1`, `b2`, ...), or `engine_absent` with the fields of the message, `tab_limit`, `bad_request`), `browser.list` (every tab: id, url, title, phase, loading, notice, frame sequence, viewport and whether it is capped, `localhost`; and whether an engine runs, pinned or not), `browser.close {tab}`, `browser.shot {tab, path}` (the newest frame decoded with `lico-frame` and written again by `lico-png` to an absolute path whose directory exists, created with mode 0600 and never over an existing file; waits up to 3 s for a first frame; `no_frame`, `exists`, `bad_request`). CLI: `lico browser open URL [--localhost]`, `list`, `close ID`, `shot ID FILE`; HTTP: the same operations through the existing JSON door; **a test shows both doors answer the same**. **Cap on the tabs: 8** (reason: each tab is a page in the engine; the engine's RSS grew about 10 MiB for one page and to 211 MiB after the screencast runs (P03, information only), and on Lico's side a tab holds at most one compressed frame of 4 MiB (the largest seen was 69,612 bytes) and, when its picture is decoded, 9.2 MB: 8 tabs bound Lico's side to under 110 MB at the very worst and under 2 MB in practice; the number is measured in the probe and may be lowered). Tabs are not saved: a host that stops ends them.

## 6. Questions the lead asked to answer in the plan

- **The memory limit that really binds the engine.** `RLIMIT_AS` cannot (V8 reserves address space: P03 note and the `address_space` remark of the SPEC). I propose `RLIMIT_DATA` (the private writable memory a process maps; the reservations that are `PROT_NONE` do not count) at **1 GiB** for the first measurement. **I do not claim it binds until it is measured:** the ignored probe (step 8) runs the engine under it, renders the fixtures (it must run), then loads a page whose script allocates more than the limit and records what the engine does (it must fail or exit while the host stays up). If it does not bind, the plan's answer is: the engine is not memory-capped, the bounds are the tab cap, the viewport cap and the page's own script deadline of the engine (30 s, its documentation), and the report says so.
- **When the engine dies:** every tab gets `Crashed` (`Failed`), the guard stops, the scratch directory is removed; the NEXT action on a tab (`browser.open`, a navigation, a reload) starts the engine once more and reopens the tabs that asked; a second death within 60 s of the restart is not restarted automatically (the tabs stay `Failed` until the person acts again); each start and end is a log line.
- **The host's idle RSS with no tab:** unchanged from M16-P08 (host 8.19 MiB; window 25.25 / 36.29 MiB): the adapter adds no thread, no socket and no allocation until a tab is opened (a registered handler and constants); measured at the end with `lico_measure` as before. **With one engine running** the counted part is the guard, the worker, the CDP client buffer and one tab model: computed at about 1 MB plus the newest frame, and measured with the fake engine and with the real one (the engine's own RSS is information, not counted).
- **Logging** as in Phase 0 section 4: engine started or ended, the exit code, the HOST of a page; never the token, a port, the credentials, a path, a query, page content or frames.
