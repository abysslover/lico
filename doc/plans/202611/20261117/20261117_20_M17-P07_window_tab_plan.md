## Objective

A browser tab in the window: an entry in the tab bar, the page's frame blitted in the right pane, an address row, the loading, absent, no-font and failed states, the guard's notices with their real reason, a help text, and the `+` entries (ordinary, and the one for this machine's own services). Input (mouse, wheel, keys, text) is P08; here the tab is shown, navigated by address, back, forward and reload, and closed.

## 1. How frames reach the window (the lead's question)

The tab models live in the host (P06); the window is a separate process. **The compressed PNG goes to the window, which decodes it** (`lico-frame` on the painter side, only for the tab that is shown, only when it is about to paint). Nothing polls and nothing is pushed that nobody asked for:

- **One blocking call, `browser.watch {tab, seq}`:** the host holds the call on a condition variable until the tab's change number is above `seq` (a new frame, a phase, a title, an address or a notice changed), then answers with the tab's row and, when the frame is newer than the window's, the newest compressed frame (base64). The window sends the next `browser.watch` only AFTER it has painted, so **a frame newer than the painter can use is never sent**: the host keeps only the newest frame (P04/P06) and the frames in between are dropped there and counted. A new frame while the window paints costs nothing on the wire.
- **No timer on either side.** The host's thread waits on the condition variable with no timeout; the window's reader thread blocks on its socket. A watch ends when the tab changes, is hidden (`browser.hide`), closed or its engine ends, and when the host stops (`stop_all` wakes every waiter). If a window dies while it waits, that one host thread stays until the next change of that tab and then ends on the failed write (bounded: one per watching connection, at most eight tabs): said plainly. The window uses a connection of its own per shown tab (a thread that blocks), as it does for a view.
- **Pacing is the host's.** The engine's acknowledgement is sent by the host at once, as in P06 (measured paced: about 31 frames a second for an animated page, one frame for a still page); the window never acknowledges.
- **Size on the wire:** a still page was 16.6 kB (1024 x 768, MEASURED); a frame is at most 4 MiB (the cap), so the line is at most 5.6 MB of base64, held once by the reader and freed after the decode. The reader of that connection has its own line cap of 6 MiB; no other connection of the window changes.
- **New operations (the hubs reach them through the same port; socket and HTTP answer the same; `browser.watch` is allowed on both doors):** `browser.show {tab, width, height}` (the window shows the tab: the model's `show`, which starts the screencast at that size, capped at 1920 x 1200 and said), `browser.resize`, `browser.hide {tab}` (stops the screencast; the newest frame is kept), `browser.go {tab, address}` (the model's `submit_address`: the address is parsed by the model; a refusal is an error code of its own: `address_empty`, `address_scheme`, ...), `browser.nav {tab, action: back|forward|reload}`, `browser.watch`. `browser.open` and `browser.close` exist (P06). The change number and the condition variable are new in the adapter's hub (`supervisor.rs` bumps it whenever an event reaches a model); no hub changes beyond P06's port.
- **What the window knows about tabs:** the tabs it opened, and at connect one `browser.list` (a tab opened by the command line while the window runs shows up at the next list: the `+` menu and a refresh on focus ask again; said in the help). Tabs are not saved: a host that stops ends them.

## 2. The window

- **Tab kind.** Like the Call Room tabs (`call_view.rs`: `open_tabs`, `active_call`, `Action::CallTab`): a `BrowserViewState` in `ui` (open tab ids, the active one, per tab the address field, the last row, the decoded frame, the change number) and one more kind of item in `tabs.rs` geometry, with the label (the page's title, else its host), `●` while loading, `!` for a notice, `×` to close. New code goes into new leaf modules (`browser_view.rs`, `browser_paint.rs`, `browser_help.rs`, the size ratchet: `ui.rs` is 1,094, `tabs.rs` and `mod.rs` near their limits), with a few lines of dispatch in the hubs.
- **Painter.** The decoded `lico_frame::Image` (`0xAARRGGBB`, row after row) is copied 1:1 into the softbuffer surface at the top left of the content area (the same pixel format the window already uses); when the viewport is capped (area larger than 1920 x 1200) the page is drawn 1:1 and the line "the page is drawn at 1920 x 1200" is shown, so that P08's mouse mapping stays exact. At most one decoded frame per shown tab; it is freed when the tab is hidden.
- **Address row.** The existing input-line machinery for text, the cursor and the pre-edit (Korean composition shows in the address field only, as decided), driven by `lico_browser_view::AddressField` (display-free, tested in P04); Enter sends `browser.go`; Esc restores the page's address; `Ctrl+L` focuses it; back, forward and reload are buttons and keys (`Alt+Left`, `Alt+Right`, `F5`).
- **States, from the model:** starting and loading (a loading mark), `Absent` (the message of the model: release, download address, both SHA-256, the directory), `NoFont` (the tab says "no Korean font found"), `Failed` (the reason and "open the address again to start the engine"), the notices of the guard and of the engine. The tab for this machine's own services shows `LOCAL_NOTE`.
- **Notices with the real reason (two small versioned changes, tests first, each its own commit):** today the model words every 403 as "a private network", which is wrong for a refused port. **`lico-proxy 0.3.0`**: `Event` carries `reason` (`NotPublic`, `Port`, `Denied`, `LoopbackOnly`) so that the notice is exact and not guessed; **`lico-browser-view 0.4.0`**: `FetchRefused` carries the port and the reason and the model words each ("the port N is not one of 80, 443, 8080 and 8443", "this address is on a private network", "this tab opens only this machine's own services", "this port belongs to Lico"); and `help_lines()`.
- **Help text (from the model, `help_lines()`, shown in a new tab and by `F1`):** the identity sentence ("pages are told this is Lico with the Obscura engine; a page may still see a Windows platform and vendor, because the engine decides those"); the ports that load (80, 443, 8080, 8443); that addresses on this computer or a private network are refused, by number and as `localhost`; for a local tab, `LOCAL_NOTE`; the Korean input note (P08); and the exact command for the owner's first real-site check: **`lico browser open https://SITE`** (the check itself is the OWNER's, on return; no test touches a real site). The same command goes into the P09 report.
- **The `+` entries.** The new-session form (`newsession.rs`, `PROVIDERS = [claude, codex, local]`) gets `browser` and `browser (this machine)`; the form is one address line and a note; Enter calls `browser.open` (with `"local": true` for the second), never taken from a page or a link. A refusal of the address is shown at once in the form's own line (the model's reason: an unknown scheme, a port, a numeric local address).

## 3. Memory counts (mail 147 item 4)

The window with ONE shown tab at the default size (1200 x 800) must stay under **50 MiB RSS**; the idle window with no tab stays at 25.25 / 36.29 MiB (scale 1 / 2), which is what a window with no browser tab must cost: the new modules hold no state until a tab opens, no thread, no buffer. COMPUTED before measuring: one decoded frame of the shown tab is at most 9.2 MB (1920 x 1200), 3.8 MB at the default size at scale 1, and the transient base64 line and the decoder's scratch are freed after each frame; at scale 2 the area is about 2300 x 1450 and is capped at 1920 x 1200. MEASURED in the plan's last step: scale 1 and scale 2 with one shown tab at the default size, and at 1920 x 1080; if over 50 MiB the viewport is capped lower and the tab says so. The host side is as measured in P06 (6.3 MiB with no tab, 10.8 with an engine and a tab).

## 6. What I need from the lead

(a) `browser.watch` as a blocking call with no timeout (my recommendation: nothing wakes; one parked host thread per watching window) against a call with a 60 s timeout (one wake a minute per side, no parked thread forever); (b) the frame travels in the reply as base64 (my recommendation: no file on disk, a page's picture can hold private data) against a file handed over as pictures are; (c) a tab opened by the command line shows up in the window at the next list, not at once; (d) the two small versioned changes of `lico-proxy` and `lico-browser-view` as the first commits.
