# Security Of An agy Session: The Program, Its Environment, Its Permissions, Its Reach

- Status: research note (2026-11-26), changes no code; the gaps at the end wait for the owner's choice or for the owner's hands-on check (gate G3)
- Version: 1.1.0 (2026-11-27, M25-P09: the window starts every agy session in `auto`, at the owner's word; gap 2 and the table row are amended)
- Milestone: [M25](../../../milestones/202611/20261126/20261126_01_M25_agy_as_a_lico_session_milestone.md), phase P07
- Method: read from the code at the end of M25-P06 (`lico 0.8.2` with the P02 to P06 changes); what was **not** run against the real program is marked (not verified). The real `agy` was never given a turn in this milestone: it was started only to record what `initialize` and `session/new` answer, with a private empty home and no sign-in.
- The question this note answers: an `agy` session is a program that runs as the person and can do what the person can do. What does Lico fence, what does it only show, and what is left to the person's care?

## What `agy` is, in one paragraph

`agy acp` is a program of the person's own machine, started by the host as a child process in its own process group, speaking the Agent Client Protocol on its standard input and output. It signs in by itself (its own files in the person's home); Lico never reads them. It runs **as the person**: with the person's user, the person's home and every file the person can reach. Lico does not sandbox it. What Lico adds is a clean environment, a fixed set of arguments, the person's choice of who answers its permission requests, a transcript, and limits on the traffic between the program and the host.

## What is considered (read from the code)

| Concern | What holds today | Where |
|---|---|---|
| The environment of the child | The child gets **seven** names of the host's environment and nothing else (`PATH`, `LANG`, `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME`): the environment is cleared first. A key or a token the host was started with, a launcher's variable, an `ANTHROPIC_*` or `GOOGLE_*` name, `LICO_*` and `SSH_AUTH_SOCK` do not reach it. `HOME` and the `XDG_*` names are kept on purpose: they are where the program looks for its own sign-in and settings. | `agy/mod.rs` `KEPT_ENV`, `Agy::command` |
| The arguments | Always `acp --disable-telemetry`, after any `--agy-arg` the host was given; the flag that skips the program's permissions is never passed by the host (a unit test and the window test read the program's first log line). | `agy/mod.rs` `FIXED_ARGS` |
| Standard error | Discarded (`/dev/null`): nothing the program writes there reaches a log of Lico's. | `agy/mod.rs` `command` |
| Stopping it | The program leads its own process group (`process_group`), and a stop or a purge of the session signals the whole group, as for the Claude and Codex programs. | `agy/mod.rs`, `session.rs` (`process_group`) |
| Who answers a permission request | **`default`: the person.** A request of the program becomes an approval of the session (the card and the notification of every other approval). **`auto`: the host**, with the narrowest yes the request itself offers (`allow_once`), and the line `[auto-allowed] <what was asked>` written first in the transcript; never an `always` option; `cancelled` when the request offers none. Since `0.9.1` (M25-P09) the window starts every `agy` session in `auto`, at the owner's words of 2026-11-26 ("auto 는 모든 요청에 allow_once로 답하므로 원래 기본값은 모두 허용"); the person switches it to `default` in the Session menu. **The program's own flag that skips its permissions is still never passed**: in `auto` the program asks and the host answers and records, it does not stop asking. | `agy/mod.rs` (`Effect::Approval`), `agy/conn.rs`, P03 plan |
| Requests that wait for ever | A turn that ends takes its unanswered requests with it (a late answer is refused and sends nothing); at most `MAX_APPROVALS` are held, the next is denied once. | `agy/mod.rs`, `session.rs` (`drop_program_approvals`) |
| What the program may ask of the host | Nothing. The host offers it no client capability (`clientCapabilities`: no file read, no file write, no terminal), and an unknown request of the program gets an error answer (`-32601`), never an action. The program does its own file and shell work in its own process, as in a terminal; only its permission requests reach the person. | `agy/conn.rs`, `src/host/adapters/agy/capabilities.json` |
| Tools of Lico's | None. The program is started with no tool server (`mcpServers: []`): it cannot call `send`, `create`, `pane`, `computer`, `capture`, `clipboard_read` or `clipboard_write`, so Lico's tools and their approvals are not a way into the person's panes, screen or clipboard for an `agy` session. | `agy/conn.rs` (`session/new`), M25 decision D4 |
| Resuming | A conversation is resumed only by its id, and the id passes the same check as every provider's (characters and length) before it reaches the registry, a command line or a log; an unknown id ends in a plain error line, never a new conversation in its place; one session of the host holds a conversation at a time. | `new_session.rs`, P04 plan |
| The folder | Checked as for every provider (an existing directory under the allowed roots); a conversation whose folder is gone is resumed in a workspace of the host, never in a folder the window picks by guess. | `folders.rs` `check_folder`, P05 plan |
| Traffic limits | A line of the program's output is cut at 256 KiB; at most 16 inputs wait in the queue; the start waits 20 s for `initialize` and 60 s for `session/new` and then ends in an error line; a failed start leaves no process, no log and no scratch workspace. | `agy/mod.rs` (`MAX_LINE`, `MAX_QUEUED`), `agy/conn.rs` (`INIT_WAIT`, `OPEN_WAIT`) |
| What the program's words can do | Text it writes is shown as text (the same defusing of control and markup as for the other providers); a request it makes that the host does not know is shown as a note or ignored, never run. | `agy/map.rs`, the reference mapping and its three fixtures |
| Exchange with other sessions (P06) | An `agy` session can be sent to (Send to, a Call Room, an `@name` of the person) and can send by a paragraph of its answer that begins with `@name` at the start of the line. That send is **the same `calls::send` as a tool's**: the same approval card unless the person has kept the room, the same limits (20 calls a minute, 4 `@name` paragraphs to one answer, the rounds of a room, 16 deferred replies), the same target rule (Claude, Codex or `agy`; never a `local` model or a session with no provider). | `calls.rs` (`takes_part`), `mention.rs` (`dispatch_assistant_mentions`) |
| Secrets in a transcript | What the program says is recorded as it says it; the host adds no secret. The sign-in line the host writes when the program says it is not signed in names the place to sign in (a Terminal tab), not a token. | `agy/map.rs`, P05 plan |

## What is NOT covered, or only by the person's own care (the gaps)

1. **The program is not fenced.** In `auto` it may do through its own tools whatever the person can do, and in `default` it still does, without asking Lico, everything it does not ask about: the program decides which of its actions raise a permission request. Lico can answer a request; it cannot see what is never asked. *This is the same as the other providers' programs run with their own permission settings; for `agy` there is no Lico-side fence behind the question.* The window's default of `default` is the only brake Lico adds. (not verified: which actions the real program asks about)
2. **`auto` answers `allow_once` for every request, and it is now the default.** It is said in the transcript line by line (`[auto-allowed] ...`), but a person who does not know what `auto` means will not know what it allows, and since `0.9.1` it is what every new `agy` session does without being asked (the owner's decision, the same default as a Claude or a Codex session). What it allows is whatever the program asks about, once each; what the program does without asking is gap 1. `default` is one switch away in the Session menu and asks about every request. A rule that would answer some requests and ask about the others (by kind of action) is not made: it needs the real program's list of request kinds (gate G3).
3. **The option ids are the documentation's, not the program's.** The host answers with the option whose kind is `allow_once` (or `reject_once`); if the real program names its options differently, the host answers `cancelled`, which is the safe direction, and the person will see a request that never goes through. (not verified: a real permission request)
4. **The environment list means a key in the environment does not reach the program.** A person who signed in to `agy` by exporting a key (not by `agy`'s own sign-in) will see `agy is not signed in`. The remedy is the sign-in in a Terminal tab (the line says so). This was chosen on purpose (the person's keys stay out of a child that has no tool of Lico's to need them) and may surprise a person who expected the shell's whole environment to be there. (not verified: that the real program signs in by files in `HOME` and the `XDG_*` folders only)
5. **A spawn that fails is reported as `busy`.** The host's one word for "could not start it just now"; the window says so in a sentence, but the cause (a missing program, a refused execution) is in the host's log, not in the window.
6. **`--disable-telemetry` is the host's choice.** The program's own telemetry is off for every `agy` session of Lico. It is a flag of the program that the capability record lists; whether it has an effect is not verified. A person who wants the program's telemetry on starts `agy` in a Terminal tab.
7. **A prompt-injected answer can send.** An `agy` answer with a `@name` paragraph sends to a session the person has a room with or approves, exactly as a prompt-injected Claude or Codex answer can; the approval card (or the kept room) is the brake, and text of the other session comes back into the program's prompt. Nothing is sent to a `local` session, and the program has no tool to reach the panes, the screen or the clipboard (see the table). The unlimited-length reply of a peer is cut at 32 KiB.
8. **Attachments are refused** for a driver session (text only): the host says so; an image or a file is not given to `agy` at all.
9. **Handing over a whole conversation is not supported** (Claude only; the same for Codex): the person copies what they want with Send to. Since `0.9.1` (M25-P09) *Hand over conversation* from an `agy` session gives the receiver only the **number** of the conversation (an id the program made, checked for its shape before it is written into another session's input), never the text, at the owner's words of 2026-11-26; the program's own files are not read for it.
10. **Not verified at all:** a real turn (the sign-in, a model's answer, a real permission request, a real resume of a real conversation); that the conversation id in the program's own files is the same text as the protocol's `sessionId` (the host test uses the same text on both sides); that `session/cancel` would stop a turn (the host never sends it: a turn cannot be stopped from the window except by ending the session).
