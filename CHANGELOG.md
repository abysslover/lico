# Changelog

Release and milestone history for Lico. Implementation proceeds on reviewed
`phase/*` branches, reaches `main` on owner merge approval (G4), and records a
named `milestone/Mxx-<name>` branch at each milestone's closing commit (see
[CONTRIBUTING.md](CONTRIBUTING.md) and [PLAN.md](PLAN.md)). Resource numbers
below are measured on the Linux `hostd` + hand-drawn native client build
(idle window limit `< 50 MiB` RSS; `10 -> 100` hidden-session growth limit
`<= +10 MiB`), and two clean clones build byte-for-byte identical release
binaries (`python3 -m lico_measure.suite acceptance`).

## Unreleased, after 0.9.1 — 2026-11-27 (`M25-P13`)

- **The sign-in is a screen of pictures for every provider** (M25-P13, the owner's words of 2026-11-27 after an agy account had been signed in): the steps are pictures of the wizard's size (Open, Sign in, Code; a tick on the ones done, the ring on the one to do, grey for the rest; Codex has no Code picture until its program asks for a code), the address stands in a box with two buttons (open, copy), the code is pasted or typed into a box with two buttons (paste, send) and drawn as stars, and a sign-in that ended without success shows a cross and a picture, Again, that starts it again. The text lines under it stay the model (the dump, the keys, the tests); the host and the protocol are unchanged. Four new icons: `check`, `cross`, `copy`, `paste`.

- **Guide**: `doc/manual_end_to_end.md` `1.42.0`.

- **Highlights** (the owner's words after trying `0.9.0`, kept in the milestone):
  - **The conversation begins folded** (M25-P09): only what you wrote begins open; the answer of an agent and a text from another session begin as the one-line pill and a click opens or folds them; the switch is `More > Settings > Start answers folded: on / off` (default on). A selection or a copy that holds a folded block gives its whole text, not the pill (this changes the pill's copy of `0.8.2`).
  - **agy begins in `auto`** (M25-P09): the New session picture, a Chats card of an agy conversation and the form start an agy session in `auto`, where the host answers each permission request once with `allow_once` and writes `[auto-allowed] ...` first (the owner's "bypass permission on" read as the host's own auto; the program's own flag that skips its permissions is still never passed); `default` is one switch away.   - **A Bot session** (M25-P10): the toolbar's `New Home session` is `New Bot session` (a robot's head, the id `new_bot`), also in the Session menu, the wizard and the hints; the place stays Home (`lico://home`), only the name of the session changes.

An agy session takes the account asked for, else the default agy account, else the person's own home as before; it is shown as `agy | <account>` and keeps its account when resumed.
  - **The guide** (`doc/manual_end_to_end.md` `1.41.0`), **the protocol note** (`0.1.18`) and **the security note** (`1.2.0`, gaps 11 to 13) say all of this.
- **Not verified by any test**: a real turn of the real `agy` and, new here, **the real Google sign-in of an agy account and where the real program keeps its token** afterwards (a file under the account's home, or the system's key store: then two accounts would share one login). The tests use a simulator of `agy acp` and a double of its sign-in; this is the owner's hands-on check (gate G3).

- **Components**: unchanged (`lico-browser-view` `0.9.0`, `lico-vt` `0.1.0`, `lico-engine` `0.1.0`, `lico-frame` `0.2.0`, `lico-cdp` `0.3.0`, `lico-cdp-fake` `0.3.0`, `lico-proxy` `0.4.1`).

- **Known limits** (new, with those of `0.9.0`): the closed conversations of an agy account's private home are not listed in Chats (the list reads the person's own home); no quota disc for an agy account; the account of a running agy session cannot be switched (`session.rebind` is refused); no SSH agy account; the wizard's agy picture has no account step (it takes the default agy account); an agy conversation resumed by its id with no account runs in the person's own home; one test of the `lico-proxy` component (`a_denied_port_is_refused_for_loopback_in_every_mode_and_a_public_destination_on_that_port_is_not_touched`) read a connection count right after a connect and failed once under load (it passes alone; the component is unchanged); text only for agy; a turn cannot be stopped from the window; the whole cold suite takes more than `180 s`; the engine's control socket still has no password; the terminal and the program `agy` are not fenced.

## 0.9.0 — 2026-11-26 (`M25`)

- **Milestone**: [M25 agy as a Lico session](doc/milestones/202611/20261126/20261126_01_M25_agy_as_a_lico_session_milestone.md) ([release report](doc/reports/202611/20261126/20261126_08_M25-P08_release_0_9_0_report.md)); a minor release (level C of the owner's order of 2026-11-24: `agy` becomes a session of Lico's, not a program in a terminal); it carries everything since `0.8.2` (M25-P01 to P07, six code commits and the note); the version is in `e4b7ca5`, the last code commit is `030edf0`; the file of the release build is `11,545,760` bytes (`0.8.2`: `11,454,064`).
- **Highlights**:
  - **agy is a session** (M25-P01 to P05): the host runs `agy acp` (the Agent Client Protocol on the program's standard input and output) as a driver kind of its own, with its own transcript; the **agy** picture of New session starts one at once in the folder the left lists (no account step, no model), a card of an agy conversation in Chats resumes it by its id (never a new conversation in its place, one session per conversation), the tab begins with `A` and the strip, the header and the list say `agy` with no account word. The terminal path of levels A and B for a conversation is gone; the Terminal picture and typing `agy` in a terminal stay.
  - **You decide what it may do** (M25-P03): every permission request of the program is an approval of the session in the mode `default` (the window's start mode); in `auto` the host answers each request with the narrowest yes the request offers and writes `[auto-allowed] ...` first, never an `always` choice; the flag that skips the program's permissions is never passed. The child gets seven names of the host's environment and `--disable-telemetry`.
  - **A peer like the others** (M25-P06): Send to, an `@name` of the person and a Call Room work between an agy session and a Claude, a Codex or another agy session; the program has no tool of Lico's, so its answer's paragraphs that begin with `@name` at the start of the line are the sends (the same approval and limits as a tool's `send`).
  - **The guide** (`doc/manual_end_to_end.md` `1.37.0`, the section *agy sessions*) and **the security note** ([Security of an agy session](doc/plans/202611/20261126/20261126_14_agy_session_security_note.md)) say all of this and what Lico does not do: the program is not fenced, runs as you and decides which actions ask.
- **Not verified by any test**: a real turn of the real program (the sign-in, an answer, a real permission request, a real resume, the conversation id in the program's files being the protocol's session id). The tests use a simulator of `agy acp` and fixtures read from the program's documented shapes; this is the owner's hands-on check (gate G3).
- **Measured**: the whole cold suite `698` tests in `149` files, three runs: `215.5 s` (load `9`), `199.4 s` and `200.4 s` (load `6`), all `698/698`, peak `1,054.3 .. 1,089.0 MiB` of the bound `1,536`; **no run was inside the limit of `180 s`** (`0.8.2`: `676` tests, `204.7 .. 271.8 s`): the suite grew by `22` tests and is over the limit also on a quiet machine, the limit stays and its judgement is the owner's; the commit hook's own run `623/623` in `194.4 s` (its limit `300 s`; the by-hand run before it peaked at `1,725.2 MiB` in the first build after the version change, over the bound of `1,536`, as at `0.8.2`, and the build was skipped by hash afterwards); `cargo xtask check`, `graph` (`279` modules, `79` nodes, the cycle of the hubs `50`, unchanged: the agy modules did not join it), `verify` and `system` (10 system tests, `92 s`, the longest `23.2 s`) pass; the clean-clone acceptance passed in `111.1 s`. - **Components**: unchanged (`lico-browser-view` `0.9.0`, `lico-vt` `0.1.0`, `lico-engine` `0.1.0`, `lico-frame` `0.2.0`, `lico-cdp` `0.3.0`, `lico-cdp-fake` `0.3.0`, `lico-proxy` `0.4.1`).

- **Measured resources**: idle window `24.76..25.11` / `35.82..36.23 MiB`, `10 -> 100` hidden growth `+0.41 MiB`
- **Highlights**:
  - **Find Local LLM servers, read-only and on demand.** `Session > Find Local LLM servers...` (a dialog that scans only on Enter or a click), `lico llm discover [--ssh-host HOST] [--all-users]`, `POST /v1/llm/discover`, and the tool `llm_endpoints` (which asks the person each time). It lists the listening TCP ports of your own processes (all users' ports only when asked) that answer like an OpenAI-compatible server (`GET /v1/models`) or an Ollama server (`GET /api/tags`): kind, address and whether it listens on loopback or all addresses, whether it wants a key (reported, never tried), its model ids and the name of its process.
  - **Careful by construction.** Only sockets that listen on the machine itself, at the machine's own address; a quiet connection first, so a server that speaks first (SSH, a database) is sent nothing; HTTP/1.0 GET with no body, credential or cookie, no redirect followed, at most 64 KiB read, at most 64 ports, 8 seconds; nothing runs in the background, nothing is stored, no other program's configuration or key file is read.
  - **ssh hosts the same way**: a bounded Python 3 script run in batch mode (20 seconds, 128 KiB of output) with clean words for an unreachable host, a missing `python3`, a timeout, too much output, a host that is not Linux. Using a found server is a later step.
