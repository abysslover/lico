# The browser adapter (`browser/`) — specification

Version 2.0.0 (M20-P01: the engine is Moli, held by the component `lico-engine`; 1.0.0 was M17-P06 with Obscura). Plan and approvals: `doc/plans/202611/20261117/20261117_19_M17-P06_browser_host_adapter_plan.md` (approved by the lead under the owner's delegation, mails 149 and 150). **MEASURED** facts about the engine are in the two measurement notes of M17; marks below say what is proved by a test of this crate.

## What it is

A browser tab with no window yet. The host starts the engine (Moli, a pinned release, held by `lico-engine` with its own version and contract number) only when a tab asks, behind `lico-sandbox` and the fetch guard `lico-proxy`, drives it with `lico-cdp`, keeps one `lico-browser-view` model per tab, and ends the engine with the last tab. It plugs in through the operations port of `driver.rs` (`register_ops`, `ops_valid`, `ops_call`, `stop_all`) and is registered once from `unified.rs`; no hub names it, so the strongly connected component of the module graph is unchanged.

## Operations (socket and `POST /v1` answer the same: one validation and one dispatch)

| Operation | Fields | Answer |
|---|---|---|
| `browser.open` | `url` (http or https), optional `local` (`lico browser open URL --local`: an explicit act of the person, off by default, never taken from a page or a link: this tab may reach this machine's own services and no other site) | `tab` (`b1`, `b2`, ...), `phase`; `phase` `absent` with `release`, `download`, `archive_sha256`, `engine_sha256`, `directory`, `put` when the engine is not installed. Errors: `bad_request`, `tab_limit`, `engine_unsafe`, `engine_not_pinned`, `engine_setting`, `engine_unreadable`, `engine_fence`, `engine_failed` |
| `browser.list` | none | `tabs` (tab, url, title, phase, loading, notice, viewport, has_frame, local, unpinned, ...), `engines` (one per network class: running, unpinned, what the engine says it is), `max_tabs` |
| `browser.close` | `tab` | `closed`, `engine_stopped` (true when it was the last tab of that engine); `unknown_tab` |
| `browser.shot` | `tab`, absolute `path` | the newest frame decoded by `lico-frame` and written again by `lico-png` to a NEW file of mode 0600 (never over a file); `width`, `height`; waits up to 3 s for a first frame; errors `no_frame`, `exists`, `bad_request`, `write_failed`, `unknown_tab` |

## Limits

At most **8 tabs** (`MAX_TABS`) in all: each is a page in the engine; on Lico's side a tab holds at most one compressed frame (4 MiB cap, so 32 MiB for eight, COMPUTED) and, while it is painted, one decoded picture (9.2 MB at the largest size). At most **two engines**: one for ordinary tabs (the guard allows public addresses only) and one for tabs opened with `local` (see below); each has its own guard. A tab opened from the command line is shown at 1024 x 768 so that it has a screencast.

## The engine file

`DATA/lico/browser/moli-v1.1.25/moli` (DATA is `XDG_DATA_HOME`, else `HOME/.local/share`; the folder name is `lico_engine::dir_name()`). It is one file: the archive's other files (readme, licences) are judged by the listing check and never written. When it is absent and a tab is opened, Lico installs it (`installer.rs`: curl, a listing check by tar, the pinned hashes, one member taken out with `--strip-components=1`, one atomic rename; `lico-engine` holds the pins and the pure checks; M17-P10, requested by the owner in the chat, 2026-11-17, wording approved by the lead, to be confirmed by the owner); the person's own manual steps are the fallback. Accepted only if the directory and EVERY directory below the home directory down to it are real directories (no symbolic link) owned by the user and not writable by group or others, and the file is a regular file of the user, opened once without following a link, not writable by others, with an execute bit. The open file is hashed from its descriptor (SHA-256, product constants) and run through THAT descriptor (`lico_sandbox::confine_fd`): what runs is what was hashed, whatever is put at the path afterwards. **No environment variable and no flag skips the hash.** The only other engine is the one named in the owner-only file `browser.json` of the state directory (`{"engine_dir": "/absolute/path"}`, a folder with a `moli` file; a regular file of the user with no group or other rights; there is no operation to set it); every tab of such an engine shows "running an engine that is not the pinned release". A damaged setting is an error, never a fall back. A setting of 0.6.2 that only says `stealth` names no engine and is read and ignored (the engine has no such switch).

**The host and the engine meet at the engine contract of `lico-engine` (number 1, `HOST_CONTRACT` in `engine.rs`, a compile-time assertion that the two are equal).** A new upstream release, a patch of Lico's on it, or another engine is a change of that component's record and nothing here.

## The fence (decided by the lead, mail 149)

Read and run the engine's directory and `/usr`, `/lib`, `/lib64`; read `/etc/ld.so.cache`, `/dev/urandom`, the Korean font directory and the system's CA bundle FILE (the first of four usual places that is a file; passed to the engine with `--ca-cert`, because its default is a link the fence blocks); write one scratch directory (mode 0700, under the state directory, removed at the end) and `/dev/null`; TCP connect to the guard's port ONLY; bind the CDP port. Arguments: `serve --host 127.0.0.1 --port N --layout --resource --screencast-interval-ms 100 [--ca-cert PATH] --log-level warn`. Environment: `HOME` and `TMPDIR` (the empty scratch directory: the engine needs a writable temporary folder), `FONTCONFIG_FILE` (a file the host writes in the scratch directory, naming `/usr/share/fonts`, the Korean directory and a cache directory in the scratch), the proxy (`HTTP_PROXY`, `HTTPS_PROXY`, `http_proxy`, `https_proxy`, `ALL_PROXY`) with per-start credentials of the guard; the credentials are never on a command line. **The engine has no password on its CDP socket** (it checks the `Origin` header, `--remote-allow-origins`, which stops a web page and not a program of this machine): the tab and `browser.list` say so (`socket_password: false`), and the fence is what keeps a page from using it. The socket path is made by the engine at each start and is read from its discovery page (`GET /json/version`, bounded, the host and the character set checked: `map::socket_path`), never assumed. Limits: `RLIMIT_DATA` 4 GiB (it stops a runaway page; it is not a tight cap) and 1024 open files. MEASURED with Obscura (P06 probe): at 1 GiB the engine cannot start (V8 fails to reserve its code range); at 2 and 3 GiB it starts and a page that allocates without end stops it; at 4 GiB the same, and it is the first value that is not flaky; Moli is a V8 engine too and starts under 4 GiB (MEASURED, the Moli trial). The ports are picked by Lico (a bind error is retried up to 3 times with a log line). Moli keeps its cookie store as files in its scratch folder (`moli-storage-*/cookies.sqlite`, MEASURED in M20: the only files it has open besides sockets), so a cookie lives as long as the engine and goes with the scratch folder when it ends; nothing is written anywhere else. What the fence does not close is on the first screen of the P03 measurement note.

## Processes, threads, wake-ups

No process, thread or socket exists without a tab. One thread per engine (it spawns the engine, so the engine's death-with-parent signal follows it) owns the CDP client, feeds the models, executes their effects and ends everything at the end. **While an engine runs that thread wakes ten times a second** (the client's 100 ms read timeout) and so does the guard's accept loop (20 ms): the first item of the input phase removes the first, and the guard's accept poll is reported with the measured CPU time. The engine is ended with `Browser.close`, then its process group is killed after one second; the host's stop ends every engine first. An engine that dies on its own gives its tabs the `failed` phase, is cleaned up (guard stopped, scratch removed), and is started again by the next `browser.open`.

## What a page can and cannot do

Nothing from a page reaches a Lico operation, tool, session or clipboard: the host reads only a frame (decoded by `lico-frame`), an address, a title and the engine's navigation events, all cleaned and bounded by the model. The honest user-agent `Mozilla/5.0 (X11; Linux x86_64) Lico/VERSION Moli/RELEASE` is set for each page session (`Moli/unpinned` for an unpinned engine): `Emulation.setUserAgentOverride` works on Moli, MEASURED in M20 (the page's request header and `navigator.userAgent` both carry it), so no start argument is needed. The page may still see a Windows `platform` (`Win32`, MEASURED) because the engine decides that. There is no stealth switch: the engine has none, and the owner's earlier word ("Lico can use stealth") stands for an engine that has one. A refused or failed fetch gives Moli its own error page (`chrome-error://chromewebdata/`, whose title is the host: MEASURED in M20; Obscura gave a blank page): the guard's refusal (403, 502, 504) becomes a notice (host only) in the loading tabs with that host, else in every loading tab (the guard does not know the tab: a limitation). Moli has no check of its own for a private address when it goes through a proxy (its source: the proxy "owns target DNS/admission"), so the refusal is the guard's alone: an ordinary tab to `localhost` or to a number on this computer reaches nothing (MEASURED in M20 with the real engine: the fixture saw no request) and says "the engine refuses addresses on this computer or a private network, by number and as localhost" (the text is the tab's, from the guard's refusal). Obscura refused them itself; Moli does not need to.

## The tab for this machine's own services (`local`, mail 151: the opt-in must not become a way in)

The engine of `local` tabs is the same engine started the same way (M20: Moli has no private-network variable to set and none is needed: MEASURED with the real engine, a local tab loads a page of a fixture on loopback, by the name `localhost` and by `127.0.0.1`, through its guard); what differs is its guard and its own scratch folder. The enforcement is outside the engine: (1) its guard allows loopback destinations ONLY (`Policy.only_loopback`: no public address and no other private range, so a hostile public page can never load in an engine that can reach local services, and a redirect from a developer page to a public host is refused with a notice); (2) every guard, in every mode, refuses a loopback destination on a port of this machine that no page may reach (`Config.deny_port`): the host's own loopback HTTP door (told by `host.rs` through `driver::note_listening`) and every running engine's CDP port and guard port (`reserved.rs`), so a page cannot reach Lico through the guard; (3) the fence still lets the engine connect to its guard's port only. The tab shows `LOCAL_NOTE` ("this tab can reach services on this machine and no other site"). System-test proof (fake engine, a fixture that counts): an ordinary tab to `localhost` reaches nothing, a local tab loads the loopback fixture, a LAN-range address and the host's own door are refused; the public case is a component test of `lico-proxy` with a fake resolver and connector.

## Logging

The host's log says: the engine started or ended, its exit code, the HOST of a page, a bind retry, a failed call. Never a token, a port, a credential, a path, a query, page content or a frame.
